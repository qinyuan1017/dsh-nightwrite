# 长夜 · i18n 骨架

这一层只交付**键表 + 取值函数 + 抽取器**，`src/*.js` 里的文案一个字都没改，
所以现有渲染结果与 323 条冒烟断言完全不受影响。

## 目录

| 文件 | 作用 |
| --- | --- |
| `locale/zh.json` | 从 `src/*.js` 抽出来的界面文案，**中文原文即键**（741 条） |
| `locale/en.json` | 同键英文译文（741 条，与 zh 一一对应） |
| `lib/i18n.js` | 纯数据 + 纯函数：`t()` / `LOCALES` / `DEFAULT_LOCALE` / 词表注册 |
| `scripts/gen-i18n.mjs` | 抽取器：扫 `src/*.js` 重建 `zh.json`；`--check` 校验是否漂移 |

## 为什么用「中文原文当键」

gettext 风格。理由不是偏好，是工程量：

- 18 个片段、741 条文案。手写 `cockpit.title` 这类语义键要先读一遍全部片段再编一套命名，
  编出来还必然不一致；而且第二次改动就要重新对一遍。
- 原文当键天然稳定：同一句文案永远同一个键，重新抽取不漂移，
  `en.json` 的译文不会被下一版抽取打乱顺序或换键名。
- 接入时 `t('保存')` 和原来的 `'保存'` 长得一模一样，diff 里一眼能看出哪句被包了。

## 现在怎么用

```js
import { t, setLocale, registerCatalog } from './i18n.js'
import zh from '../locale/zh.json' with { type: 'json' }   // 或自己 readFileSync
import en from '../locale/en.json' with { type: 'json' }

registerCatalog('zh', zh)
registerCatalog('en', en)

t('保存')              // → '保存'（默认语言 zh，与原界面完全一致）
setLocale('en')
t('保存')              // → 'Save'
t('没登记的键')         // → '没登记的键'（漏翻的失败模式是「还是中文」，不是「露出 key」）
t('共 {n} 条', '共 {n} 条', { vars: { n: 5 } })   // → '共 5 条'
```

要点：

- **默认语言是 `zh`**，所以只要你不 `setLocale`，接入后界面一个像素都不变。
- 查不到就走 `fallback` → 再查不到就返回 `key` 本身。
- 占位符用 `{name}` / `{0}`；缺参数时**原样保留占位符**，不渲染成 `undefined`。
- `lib/i18n.js` 不读文件、不看环境变量、无副作用，宿主打包成单文件也不影响。

## 后续接入路径（建议按这个顺序做，别一次全改）

1. **先接「壳」**：`src/90-shell.js` 的导航标签（`PAGES` 的 `label`、`PANEL_ID` 标题）。
   这一层只有 ~26 条文案，改完冒烟测试只影响「标题文案」类断言。
2. **再接受众最高的两页**：`src/20-cockpit.js`（驾驶舱）与 `src/70-settings.js`（设置）。
   这两页纯文案多、逻辑少，风险最低。
3. **然后是表单密集页**：`src/25-plan.js`、`src/30-studio.js`、`src/40-review.js`。
   这里要注意：文案出现在 `h('button', {...}, '保存')` 这类位置，包一层 `t()` 即可，
   但**不要动 state 里存的字符串**（那是数据，不是文案）。
4. **最后才是长句/说明文**：`locale/zh.json` 里长度 > 40 的 ~35 条。
   这些是解释性段落，改动会动到快照类断言。

每一步之后跑：

```bash
node scripts/gen-i18n.mjs --check   # 确认键表与源码同步
node build.mjs && node test/smoke.mjs
```

## 抽取规则（`gen-i18n.mjs`）

宁可少抽，不要抽错。**不抽**的东西：

- 注释里的中文（不是文案）
- `console.*` / `throw new Error(*)` 里的中文（日志与异常，不上屏）
- `src/15-mock.js` 整份（演示用的假书稿，不是界面文案，417 处）
- 含 `${…}` 的模板串（带插值，静态表放不下，247 处，留给后续带插值那一批）
- 以空白开头的拼接片段（`' 字'` 这种半个词，3 处）
- 字面量里带 `\n` 的提示词块（多行正文，7 处）
- 长度 > 160 的长段落（1 处）

重新抽取后如果 `zh.json` 有变化，说明有人改了界面文案 —— 这是预期的，
跟着跑一次 `node scripts/gen-i18n.mjs` 并把新增条目补进 `en.json` 即可。
`en.json` 缺键时 `t()` 会退回中文，不会崩。

## 已知取舍

- **没做语言选择 UI**。设置页里没有「界面语言」这一项 —— 加控件要改 `src/70-settings.js`，
  超出本次范围。开关留在 `setLocale()` 这一层，谁需要谁调。
- **`en.json` 是人工翻译**，专业术语（账本 / 冷读 / 硬伤 / 派单 / 收口）按
  《长夜》的语义译，不是逐字直译；后续要改统一在 `en.json` 里改。
- **插值文案还没进表**（247 处 `共 ${n} 条` 这类）。要收它们得先把抽取器升级成
  能生成 `共 {n} 条` 模板，并验证 18 个片段的插值上下文，属于下一批工作。
