## 二、从数字里能读出什么写法

### 1. 一章 2100 字，80 段，每段 26 字

这不是「文风偏好」，是**载体约束**。手机屏幕一屏大约 15-20 段，2100 字 / 80 段刚好是「刷四五屏一章」。段长 26 字意味着读者每次视线移动只吃一小口。

推论（可直接执行的写法）：
- 一段只放一个动作或一句台词。**两个动作就分两段。**
- 一段超过 50 字就检查：是不是把「他说」和「他想」塞在了一起。
- 一章 80 段上下；写到 60 段还没到章末，说明情节密度不够，在同一个场景里打转。

### 2. 句长中位 25 字，但两头都有肉

p10 = 9 字、p90 = 40 字、最长 76 字。这说明作者**在按情绪换句长**：
- 紧张/动作 → 短句堆叠（9 字左右）
- 铺垫/心理 → 长句缓推（40 字左右）
- 全书最长 76 字那种句，是刻意留的「一口气读完」的长句，一章最多一两处

反过来说：**如果一章里句长分布很窄（全是 25 字上下），那就是平的。** 这条比任何「AI 味词表」都更能抓到机器稿——机器倾向于均匀输出。

### 3. 五分之一段落由对白起头

21% 的段落第一句是引号开头。这意味着场景推进大量靠说话，而不是靠叙述。写到某个场景觉得闷，先查这条：这一段是不是连续五段都在叙述、没有一句人话。

### 4. 段长 p99 只有 50 字，说明「不写长段」是硬约束

p99 = 50 意味着 99% 的段落都在 50 字以内。这不是巧合，是长期训练出来的手感。新手最容易犯的错就是一段写 150 字讲完一整段心理活动——在这个载体上，这样的段落会被读者直接跳过。

## 三、检测器阈值应当怎么定（方法，不是数字）

现在的 28 条规则，阈值都是我按阅读经验拍的。正确的定法：

```
对每条规则，在语料池的每本书上算 hits/千字
→ 取全部书的 p50 与 p90
→ 建议阈值 = p90 × 1.2（留一档余量）
→ 如果当前阈值 < 语料 p90，说明这条会天天报警，必须调
```

这套已经实现：`lib/corpus.js` 的 `deriveThresholds()`，界面在设置页「语料池」卡的「量一遍阈值」。

**样本不够时不许下结论。** 现在只有 1 本书，`deriveThresholds` 的 `minBooks = 3` 会直接返回「池子里只有 1 本书，还不够 3 本」。这是故意的——用 1 本书定阈值，等于把一个人的习惯当成行业标准。

要达到能定阈值的样本量，按公开拆书语料的量级（5584 章）折算，需要 **约 26 本 214 章的书**。这是时间问题，不是代码问题。

## 四、数据抓不到的，必须交给 agent

下面是这份语料**量不出来**的东西。写清楚这条边界，比假装能算更重要。

| 抓不到的 | 为什么抓不到 | 交给谁 |
|---|---|---|
| 人物弧光有没有推进 | 「他变了」不是字符串特征，要看前后 20 章的行为对比 | `changye-character-designer` + `changye-character-state` |
| 因果链断没断 | 「因为 A 所以 B」在文本里常常只写 B，A 在 5 章前 | `changye-story-architect` + `changye-continuity-pass` |
| 爽点有没有真的兑现 | 读者等的是一口气，不是某个词 | `changye-emotional-payoff` + `changye-reader-proxy` |
| 章末钩子强弱 | 可以数「章末最后一句多长」，但强不强要看它有没有制造未闭合的问题 | `changye-chapter-hook` |
| 伏笔收没收 | 埋和收是两次出现，中间隔几十章，且用词不同 | `changye-foreshadow-ledger` |
| 这个世界合不合理 | 需要理解设定本身的逻辑 | `changye-worldbuilding-bible` |

**一句自律**：能用正则算的，就用正则算；算不出来的，明确说算不出来，交给 agent。用正则假装能判断「这本书好在哪」，是给自己造假证据。

### 从频次表能看出一件事

硬拦的 12 条里，有 8 条在真稿上是 0 命中或接近 0。这说明**硬拦的定位是对的**：它拦的是「机器稿和手滑」，不是「文风」。一首真人写的书，正常情况下永远碰不到硬拦。

反过来说：**如果一章被硬拦碰到 3 次以上，那章大概率真有问题**，而不是检测器太严。

## 六、这份文档怎么长

现在只有 1 本书的样本量，所以：

- 第一节的数字是**这一本**的，不能当行业标准；
- 第二节的写法推论是从这一本反推的，可能有作者个人习惯；
- 第三、四、五节的方法是**可迁移**的，换多少本都成立。

增长路径：
1. 往设置页「语料池」里加书（自己的稿子优先，公版书次之）
2. 加够 3 本，`corpus.thresholds` 开始给分位数
3. 把分位数写进各书的 `lint-calibration.json`（「量一遍阈值」按钮已实现）
4. 加够 26 本，统计量级追平公开拆书语料
5. 每加一批书，重跑 `node test/_doccraft.mjs`，更新第一节那张表

**这一节的数字会变，方法不会。**
