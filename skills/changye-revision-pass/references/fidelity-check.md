# 改稿时的保真检查

> 适用：三遍法每一遍改完、落盘之前读这份；判「我这次改动有没有把不改的东西改掉了」时读这份。

改稿最贵的错误不是没改好，是**改了不该改的**。SKILL.md 列了七条禁止事项，但禁止事项是「不许做」，缺的是「怎么验证没做」。

这份给五项可测的保真指标，改前改后各测一次，对表。

---

## 一、五项保真指标

| 指标 | 算法 | 容差 |
|---|---|---|
| **字数变动率** | (改后−改前) ÷ 改前 | 修 Bug：±5%；提质量：±15% |
| **段数变动率** | (改后段数−改前段数) ÷ 改前段数 | 修 Bug：0；提质量：±20% |
| **细纲三点覆盖率** | 三条 summary 各能被正文指认 | 必须 3/3 |
| **钩子功能一致性** | 改前后钩子类型是否同类 | 必须同类 |
| **账本外新增设定数** | 改后正文里出现的、账本没有的新名词/新规则 | 必须 0 |

### 为什么是这五项

- 字数变动：抓「顺手扩写」
- 段数变动：抓「顺手重排」
- 细纲覆盖：抓「为了通顺改剧情」
- 钩子功能：抓「把新信息钩子改成动作悬停」
- 新增设定：抓「为了解决矛盾新编一个东西」

---

## 二、字数与段数的具体算法

### 字数

不含标点、不含空白、不含标题（与全局口径一致）。

```
改前字数 W1、改后字数 W2
变动率 = (W2 − W1) ÷ W1
```

| 变动率 | 判定 |
|---|---|
| −5% ~ +5% | 正常（修 Bug 应在此区间） |
| +5% ~ +15% | 提取质量改动的合理范围 |
| +15% ~ +30% | 超标，需逐段说明为什么加 |
| >+30% | 已构成扩写，不是改稿 |
| −5% ~ −15% | 提质量压缩，合理 |
| <−15% | 超标，可能是删掉了不该删的 |

### 段数

```
改前段数 P1、改后段数 P2
```

**修 Bug 类：P2 必须等于 P1。** 理由：修 Bug 不该改变段落结构；如果段数变了，说明改法越界了（比如把一句错日期改成加了一整段解释）。

**提质量类：|P2−P1| ÷ P1 ≤ 20%。**

## 三、细纲三点覆盖率

SKILL.md 要求「本回 summary 三点，改完还成立吗」。判定方法：

对三条 summary 各做一次**指认测试**：

```
对第 i 条 summary S_i，在改后正文里找出满足以下三条的部分：
  1. 有一个具体的段落（或连续段落）承担它
  2. 这一段的内容与 S_i 不矛盾
  3. 这一段的量级与 S_i 相称（如果 S_i 是「他失去族籍」，
     只有一句「他被赶出来了」不算覆盖）
```

**三条全过 = 3/3。任意一条不过 = 不通过，必须回改。**

### 常见失败：第 3 条（量级）

- summary：「沈砚查出父亲的死与二叔有关」
- 改后正文：「他想起二叔那天神色不对。」
- → 不覆盖。**因为「想起」不等于「查出」**，量级差了一个动作。

### 常见失败：summary 被拆散

summary 的三点原本是三个连续的段落，改后分散到章首、章中、章末。**这算覆盖**，只要三处都在。

## 四、钩子功能一致性

SKILL.md 要求「章末钩子的功能必须保留，可以换写法」。

### 钩子的五个功能类型（判定表）

| 类型 | 特征 | 修改时的对换规则 |
|---|---|---|
| **新信息** | 末段揭示了一个前文不知道的事实 | 只能换成另一个新信息，不能换成动作悬停 |
| **急追问** | 末段提出一个必须立刻知道答案的问题 | 只能换成另一个急追问 |
| **动作悬停** | 末段一个动作被打断 | 只能换成另一个动作悬停 |
| **威胁预告** | 末段出现一个明确的威胁 | 只能换成威胁预告 |
| **无效** | 收束/总结 | 无效状态不许保留，必须改成前三类之一 |

### 判定方法

读末 150 字，问：**读者在最后一句话后产生的下一个念头是什么？**

| 念头 | 类型 |
|---|---|
| 「原来是这样！」+ 一个新的疑问 | 新信息 |
| 「他怎么办？」（紧急） | 急追问 |
| 「然后呢？」（画面停住） | 动作悬停 |
| 「要出事了」 | 威胁预告 |
| 「……哦。」（没有念头） | 无效 |

### 保真判据

```
改前类型 == 改后类型 → 保真通过
改前「无效」→ 改后任意有效类型 → 保真通过（这是修 Bug）
改前有效 → 改后「无效」 → 保真失败
改前类型 A → 改后类型 B（都有效但不同） → 保真失败
```

**最后一行的理由**：不同类型钩子对下一章的期待不同。原本是「新信息」钩子，第 n+1 回的开头是按「读者已知此事」设计的；换成「动作悬停」，下一回开头就会莫名其妙。

**除非下一回细纲一起改。** 改钩子类型必须同步检查下一回细纲（见 SKILL.md 禁止事项「不许调 outline.save」——所以实际上不许换类型）。

## 五、账本外新增设定数

### 判法

对改后的每一段做一遍名词/规则提取：

1. **专名**：任何新的地名、人名、招式名、物件名 → 查 `terms`
2. **规则**：任何「不能/必须/只能」这类约束 → 查 `rules`
3. **关系**：任何「A 是 B 的 X」→ 查 `characters` / `locations.relation`

**账本里查不到 = 新增设定 = 违规。**

### 三种例外（不算新增设定）

| 情形 | 判据 |
|---|---|
| **泛称** | 「一个公差」「几个人」——没有专名，不入账 |
| **账本已有的同义表述** | 「仵作」vs「验尸的」——同指，不算新 |
| **场景临时物件** | 「桌上的碗」「门口的柴」——不承载剧情的不入账 |

### 判据边界

**问：这个新东西会不会在后文被再次提到？** 会 → 必须入账（否则后面就是断链）；不会 → 允许，但不许给它专名。

**最常见的越界**：修一个时间冲突，顺手写出「三日后，府城来人了」——「府城来人」是一个新事件，如果后文没有，就是孤岛。正确改法是改成「三日后，他听说府城来了人」，把事件降级为传闻，不新增实体。

## 六、五项的对表格式

改前测一次，改后测一次，逐项对：

```
【保真对表】
  指标            改前        改后        变动      容差        结果
  字数            2380        2412        +1.3%     ±5%(修Bug)  通过
  段数            34          34          0         0(修Bug)    通过
  细纲覆盖        —           3/3         —         必须3/3     通过
  钩子功能        新信息      新信息      —         必须同类    通过
  新增设定        0           1(「漕帮」)  +1        必须0       失败
```

**任何一项失败 = 不许落盘。** 先修好，再重测。

## 七、五项之外的三项软检查

三项不是硬指标，但发现异常要记进回执：

### 软检查 1：改动密度的均匀性

```
改动密度 = 改动字数 ÷ 改动区段字数
```

如果在改动的 6 段里，第 1 段改了 90%、第 6 段改了 5%，说明改动不均衡——很可能是改到一半就停了。判据：**同一改动区段内的密度差不应超过 3 倍**。

### 软检查 2：未改动区段的完整性

用 diff 看未点名区段有没有任何变动。**一处变动都不该有。**

diff 出变动的三种情况：
- 空白/换行（无害，但要说明）
- 标点（可能是顺手改的，要回退）
- 文字（违规，必须回退）

### 软检查 3：术语写法一致性

如果改动里提到了账本专名，检查写法是否与 `terms.name` 完全一致。**「玄铁令」写成「玄铁令牌」就是引入新写法**，需要建别名条目或回退。

## 八、保真失败的四个典型修复

| 失败项 | 典型原因 | 修复 |
|---|---|---|
| 字数 +28% | 把「改一处」做成了「重写这一段」 | 回退到只改出错点 |
| 细纲覆盖 2/3 | 改写法时把某一条 summary 的「量级」降了 | 补一个动作 |
| 钩子功能变了 | 觉得原来的钩子不够好 | 回退；换类型必须下一回一起改 |
| 新增设定 1 条 | 为了解决矛盾编了一个新东西 | 改成不新增实体的写法（降级为传闻/回忆） |

**第三行最常见也最危险**：改稿人往往觉得「原来的钩子太平」，顺手换了——这时下一回的开头设计全部作废。
