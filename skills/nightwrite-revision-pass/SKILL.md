# 定向修订

唯一被授权**重写已存在正文**的操作手册。核心纪律是：先分类，再动手；只改被点名的。

## 执行步骤

**第 1 步：把意见分成两类（这一步不写进回执不许动笔）**

| 类别 | 包含 | 允许的改动幅度 |
|---|---|---|
| **修 Bug** | 与账本冲突、伏笔断线、时间线矛盾、行为越界 | **只改出错点及其必要衔接**，不许顺手优化周围段落 |
| **提质量** | 节奏、钩子、可读性、情绪回报 | **可以改结构**，但必须保留原回细纲目标与章末钩子功能 |

分不清的，一律归「修 Bug」按小幅度处理。

**第 2 步：拉基准**

- `ledger.get`：相关 `characters` / `rules` / `foreshadow` / `terms`
- `outline.intent`：本回 `summary` 三点 + `hook`（这是改完必须仍然满足的验收标准）
- `chapter.list`：已 `accepted` 的回目（那些是硬约束，不许动）

**第 3 步：定向改，逐处留痕**

只动被点名的区段。每一处写 `原 → 新 → 依据`，「依据」必须能指向具体条目编号（审校致命 1 / 读者报告 掉分点 / 责编建议 2）。

改的时候守三条：

1. **事实不变**：`ledger` 里记的，正文不许改；要改先改账本。
2. **钩子同功能**：章末钩子的**功能**必须保留（原来是新信息就还是新信息），可以换写法。
3. **细纲不迁就**：不许为了让改写通顺而改细纲。

**第 4 步：自查三问**

1. 本回 `summary` 三点，改完还成立吗？
2. 改动的段落之外，有没有被连带影响的前后衔接句漏改？
3. 有没有引入 `ledger` 里不存在的新设定？（有就删）

**第 5 步：落盘 + 标注重走**

`nightwrite_op` → `chapter.save`。然后在回执里明确：审校要不要重走、读者报告要不要重走。

## 输入

- 待改正文（`chapter.get`）
- 改稿依据：审校报告条目 / 读者体验报告 / 责编建议 / 作者原话
- `outline.intent`（验收标准）、`ledger.get`（红线）

## 输出格式

```
【分类】修 Bug <n> 处｜提质量 <n> 处
【改动清单】
1. [修Bug] 第 <X>-<Y> 段
   原：「<≤20 字>」
   新：「<≤20 字>」
   依据：审校 致命 1
2. [提质量] 第 <X> 段
   动作：<提前引爆 / 压缩 / 换钩子 / 挪信息>
   依据：读者报告 弃书触发点
【细纲符合性】① <点1> 保留 ② <点2> 保留 ③ <点3> 保留
【章末钩子】改前功能 <…> → 改后功能 <…>（必须同功能）
【未改部分及原因】<…>
【需要重走】审校 <是/否，为什么>｜读者报告 <是/否，为什么>
```

## 检查清单

- [ ] 意见已分成「修 Bug」和「提质量」两类，有分类计数
- [ ] 每处改动都带依据编号，没有一条是「我觉得」
- [ ] 改动范围只覆盖被点名区段，没被点名的段落原样保留
- [ ] 本回 `summary` 三点改完仍然成立
- [ ] 章末钩子功能未变
- [ ] 没有引入 `ledger` 里不存在的新设定
- [ ] 没动已 `accepted` 章节的事实
- [ ] 前后衔接句检查过，没有留下断裂
- [ ] `chapter.save` 已执行
- [ ] 「需要重走」写清了是/否及原因

## 禁止事项

- 不许擅自改主线、卷结构、伏笔回收章号。
- 不许新增重大设定（新势力、新能力、新角色）。
- 不许调 `review.action`。改完不是定稿，是重新进闸。
- 不许调 `outline.save` 改细纲来迁就自己的改写。
- 不许一次改超过两章。多章同改会让人无法定位是哪处出的问题。
- 不许把「修 Bug」悄悄做成「顺便重写一整段」。
- 不许跳过「需要重走」直接宣布这章好了。
