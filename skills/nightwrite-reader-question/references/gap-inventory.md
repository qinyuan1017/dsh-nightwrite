> 适用：要把这一章该给的信息做成一张缺口清单、或者判断「该补的补在哪一段」时读这份。

# 信息缺口清点

一份好的缺口清单回答三个问题：**缺什么 / 缺它会让读者卡在哪 / 补在哪一段之后**。

写不出第三个，这份清单就没有可执行性。

## 两种缺口

| 类型 | 定义 | 处理 |
|---|---|---|
| **有意缺口** | 作者故意不给，且给了标记（有人物反应表示「这里有东西」） | 保留，但要登记 payoffAt |
| **无意缺口** | 作者以为给了，或者没意识到需要给 | 必须补 |

**判据**：这个缺口，`outline.intent` 里有对应的设计吗？

- 有 → 有意缺口，登记台账
- 没有 → 无意缺口，补

**注意**：即使 `outline.intent` 里有，但没有**标记**（读者感知不到这是故意的），仍然是无意缺口——读者不会因为作者「本来想藏」就不困惑。

## 三档缺口的清点顺序

按读者的卡点顺序清，不按文本顺序。

### 第一档：活不下去的缺口

**判据**：读者不知道**主角此刻在干什么**。

| 缺什么 | 例 |
|---|---|
| 目标 | 他要去哪、要做什么 |
| 阻碍 | 什么在挡他 |
| 位置 | 他在哪（不需要地图，但要有一个可想象的场景） |

**三缺一，读者会在前 300 字退出**（对应 `drop-off-windows.md` 的 A 窗口）。

**补法**：不补在这章开头，要补在**上一章末尾**——读者进来时应该已经知道。

### 第二档：看不懂这里的缺口

**判据**：读者知道主角在干什么，但不知道**这一段在干什么**。

| 缺什么 | 例 |
|---|---|
| 人物身份 | 突然出现一个名字，读者不知道他是谁 |
| 指代对象 | 「他」「那个人」「那把东西」 |
| 因果环节 | 为什么这样做会有那个后果 |
| 时间关系 | 这是同时、之后，还是回忆 |

### 第三档：不满足的缺口

**判据**：读者看得懂，但觉得**这信息没意思**（不算困惑，算密度不足）。

| 缺什么 | 例 |
|---|---|
| 信息的用处 | 知道了这个，但不知道它能干什么 |
| 代价 | 出事了，但不知道会损失什么 |

**第三档不是困惑，不进这份清单的必修项**，转 `nightwrite-engagement-curve` 处理。

## 「补在哪一段之后」的算法

### 基本规则

```
补入位置 = 读者第一次产生这个疑问的段落之后 1–2 段
```

**为什么不是「之前」**：提前给等于剧透，读者会觉得啰嗦（他还没想知道）。

**为什么不是「之后很多段」**：读者已经放弃理解（见 `question-vs-confusion.md` 的窗口规则）。

### 「第一次产生疑问」怎么定位

三个定位法：

**定位法一：指代第一次出现处**

```
读者第一次遇到「他」但不知道是谁 → 就是这里
```

**定位法二：动作的动机第一次被需要处**

```
读者第一次觉得「他为什么要这么做」 → 就是这里
```

**定位法三：名字第一次出现处**

```
读者第一次看到一个名字，且没有任何身份说明 → 就是这里
```

### 补入的三种形态（按成本排）

| 形态 | 做法 | 成本 | 适用 |
|---|---|---|---|
| **顺手带出** | 在已有的句子里加一个身份词 | 最低 | 缺的是身份/关系 |
| **动作夹带** | 让一个人做一个动作，动作本身说明关系 | 中 | 缺的是关系/位阶 |
| **单句交代** | 单独一句说明 | 高（会打断） | 缺的因果环节，非说不可 |

**优先级**：能顺手带出就不单句交代。

**例**（缺：读者不知道「陈主簿」是谁）：

```
（原）陈主簿走进来，把文书放在桌上。

（单句交代·差）陈主簿是管漕运文书的官员，比他高一级。

（动作夹带·中）陈主簿走进来，把文书放在桌上，没看他。

（顺手带出·好）管文书的陈主簿走进来，把文书放在桌上。
```

差别：第三种只在名词前加了三个字，读者立刻有了位置感（管文书的 = 能压他的人）。

## 清单的字段

每条缺口记六项：

```
1. 缺口编号
2. 缺什么（具体到名词，不写「背景交代不足」）
3. 读者会不会卡（会／可能／不会）
4. 第一次产生疑问的段号
5. 正文是否已有答案（有 → 位置在哪 / 无）
6. 补入位置（段号）+ 补入形态（顺手/夹带/单句）
```

**第 5 项是关键**：很多「缺口」其实正文里有，只是位置不对（见 `question-vs-confusion.md` 的子型二）。这一项能筛掉一半的工作量。

## 常见误判

| 误判 | 事实 |
|---|---|
| 「这里需要补背景」 | 多数情况不需要。读者能容忍不知道，只要不卡 |
| 「补得越多越清楚」 | 补得多会变成信息灌（单段 ≥2 条新信息就是灌） |
| 「读者应该自己推」 | 只有当推理的**材料齐了**才成立。材料不齐就是漏 |
| 「这是留白」 | 留白必须有标记（见 `question-vs-confusion.md` 误判三） |
| 「放在下一章揭」 | 跨章 = 严重困惑（窗口规则） |

## 缺口与伏笔台账的接口

有意缺口要登记：

```
ledger.upsert kind=foreshadow
  name: <缺口对应的悬念名>
  plantedAt: <第 N 回>
  payoffAt: <计划回收的回>
  status: 未回收
  note: <埋设原句｜缺的是什么>
```

**判据**：这个缺口的 `payoffAt` 写不出来 → 它其实不是有意缺口，是你还没想好要不要给。那就按无意缺口处理（补掉）。

## 全章清点的执行顺序

```
第 1 步：清第一档（活不下去）
  逐场景问：读者知道他在干什么吗？阻碍是什么？在哪？
  任一场景答不出 → 记为第一档缺口（补在上一章末尾）

第 2 步：清第二档（看不懂这里）
  逐段扫四类：人物身份／指代／因果／时间
  每一处记段号

第 3 步：对第 2 步的每条，去正文搜答案
  搜到 → 记 Y-X 距离（≤2 通过，3–4 边缘，≥5 记困惑）
  搜不到 → 记真缺口

第 4 步：给每条真缺口定位补入点
  读者第一次产生疑问的段号 + 1

第 5 步：选形态（顺手 > 夹带 > 单句）

第 6 步：有意缺口登记台账
```

## 一份完整的清单示例

```
【缺口清单】
  #1 第一档 · 缺：本章目标 | 会卡：会 | 段号：第 1 段
      正文已有答案：无 → 补入位置：上一章末尾 | 形态：单句（信息必须完整）
  #2 第二档 · 缺：「陈主簿」身份 | 会卡：会 | 段号：第 6 段
      正文已有答案：有，第 21 段（Y-X=15，严重超窗）
      → 补入位置：第 6 段之后 1 段 | 形态：顺手带出（在名词前加「管文书的」）
  #3 第二档 · 缺：第 14 段「他」指谁 | 会卡：会 | 段号：第 14 段
      正文已有答案：无 → 补入位置：第 14 段内 | 形态：顺手带出（改成人名）
  #4 第二档 · 缺：为什么送这封信会死人 | 会卡：可能 | 段号：第 18 段
      正文已有答案：无 → 补入位置：第 18 段之后 1–2 段 | 形态：动作夹带（让收信的人脸色变一下）
  #5 有意缺口 · 缺：他父亲的下落 | 已登记台账（第 3 回埋，计划第 28 回收）| 标记：有（第 3 回有人问「你父亲呢」，他没答）
【统计】第一档 1 · 第二档 4 · 有意缺口 1
【必修】#1 #2 #3 #4（#2 只需挪位置，不新增字数）
```

**注意 #2**：这一条的工作量是「挪位置」，不是「新写」。清单里必须写清这一点，否则作者会以为要重写整段。

## 一个反直觉的结论

**补缺口的最佳方式是删，不是加。**

一半以上的「读者看不懂」不是因为缺信息，是因为前面给了**多余的信息**，把关键信息淹没了。

典型：一段 300 字的环境描写里，真正有用的只有一句「碗是两只」。读者要在这 300 字里自己挑出那一句，挑不出来就是困惑。

删掉 250 字的环境，这一句自然浮起来——不需要新增一个字。

**判据**：这条缺口，能不能通过删掉周边 30% 的内容解决？能 → 优先删，别加。
