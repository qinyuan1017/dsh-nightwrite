# 伏笔台账

伏笔的唯一账本。**有埋没回收章的不许入账**——这是硬规则。

## 三态定义

| 状态 | 含义 | 判定 |
|---|---|---|
| `未回收` | 已埋，`payoffAt` 还没到 | 正常 |
| `已回收` | 在 `payoffAt` 那一回正文里兑现了 | 需正文证据 |
| `废弃` | 主动放弃，明确不再收 | 需写明理由 |

**超期**不是第四态，是`未回收`的子情况：`payoffAt < 当前章` 但仍未回收。

## 执行步骤

**第 1 步：埋设（入账四要素）**

`changye_op` → `ledger.upsert`（kind=`foreshadow`），必须有：

```
name:      伏笔名（稳定标识，不改）
plantedAt: 埋在第几回（具体章号）
payoffAt:  收在第几回（具体章号，不许写「以后」）
status:    未回收
note:      埋的时候正文里具体是什么句/什么物件（≤30 字）
```

`payoffAt` 写不出来的伏笔不许入账——那说明它还不是伏笔，只是随手写的细节。

**第 2 步：回收（要正文证据）**

收伏笔那一章写完后：
1. `chapter.get` 确认正文里确实兑现了；
2. 引用兑现的句子（≤30 字）写进 `note`；
3. `ledger.upsert` 把 `status` 改成 `已回收`。

**只说「已经收了」但引不出正文句子的，不许标已回收。**

**第 3 步：查断线与超期**

`ledger.get` → `foreshadow`，逐条对比 `chapter.list` 的最大章号：

- `status = 未回收` 且 `payoffAt ≤ 最大章号` → **超期**，必须报；
- `status = 未回收` 且 `payoffAt > 最大章号` → 正常；
- `status = 已回收` 但没有正文证据句 → **疑似假回收**，必须报。

**第 4 步：报数**

超期和假回收的条数直接进驾驶舱欠账，不要自己消化。

## 输入

- `ledger.get` 的 `foreshadow` 全量
- `chapter.list`：当前最大章号（判超期）
- `chapter.get`：回收验证需要读正文
- `outline.get`：`payoffAt` 是否落在合理卷内

## 输出格式

```
【本次操作】<埋设 / 回收 / 盘点> · <伏笔名>
【内容】plantedAt 第 <n> 回｜payoffAt 第 <n> 回｜status <…>｜note「<…>」
【盘点结果】
  未回收（未到期）：<n> 条 — <名(第n回收)> …
  超期：<n> 条 — <名>（应于第 <b> 回，已逾 <n> 章）
  已回收：<n> 条
  疑似假回收：<n> 条 — <名>（标已收但引不出正文句）
  废弃：<n> 条 — <名>（理由：…）
【落盘】ledger.upsert 成功
```

## 检查清单

- [ ] 每条伏笔都有具体章号的 `plantedAt` 与 `payoffAt`
- [ ] 没有「以后再说」的 `payoffAt`
- [ ] 标 `已回收` 的每条都引出了正文证据句
- [ ] 超期条目全部列出，没有隐瞒
- [ ] 假回收（无证据）已点名
- [ ] `name` 稳定，没有同一伏笔两个名字
- [ ] `payoffAt` 与该卷结构不冲突
- [ ] `ledger.upsert` 已执行

## 禁止事项

- 不许写正文。
- 不许评价文笔好坏。
- 不许在 `payoffAt` 空缺时把伏笔入账。
- 不许因为「这条不好收」就悄悄删掉条目——要删必须改成 `废弃` 并写理由。
- 不许标「已回收」却引不出原句。
- 不许把超期条目留在台账里不上报。
