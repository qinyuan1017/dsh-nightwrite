# 势力关系的建法

> 适用：第 3 步写 `locations.relation` 与势力网络时读这份；判「这段势力描写有没有用」时读这份。

SKILL.md 给了「谁对谁、什么态度、为什么」三要素和方向要求。这份补：**势力的四种结构、关系的五个维度、常见崩法、以及势力怎样进剧情**。

---

## 一、势力的定义与建卡门槛

### 什么算「势力」

**判据：它能不能对主角做出「支持 / 阻碍 / 无视」中的一个明确动作？**

- 能 → 建卡
- 不能（只是个地名） → 归 `locations`，不建势力关系

**例**：「陈留县」是地理；「陈留县衙」是势力（能派差役）；「漕帮」是势力（能封码头）。

### 建卡门槛

| 出场次数 | 建卡深度 |
|---|---|
| ≥10 回 | 完整：目标、资源、内部派系、对外关系 |
| 3–9 回 | 简版：目标 + 资源 + 一条对外关系 |
| 1–2 回 | 只登记名 + 功能（「他就是来传话的」） |

## 二、势力的四种结构

### 结构 A：单核

一个头目，其他人服从。

**特征**：决策快，但头目一倒就散。

**适用**：小帮派、家族、山寨。

**写法**：
```
【势力】漕帮陈留分舵
【头目】周舵主（characters id=c_zhou）
【目标】垄断城西码头；不惹官府
【资源】三百帮众、十二条船、码头的钥匙
【弱点】周舵主只有一个儿子，儿子在县学读书
```

### 结构 B：双核（对立）

两个头目互相制衡。

**特征**：内部有戏，但决策慢。

**适用**：大帮派、朝堂、门派。

**判据**：两个头目必须**目标不兼容**。兼容的双核是假的（很快会变成单核）。

### 结构 C：议会

多人投票。

**特征**：稳定但迟钝，容易僵持。

**适用**：族老会、宗门长老会。

**写法要点**：必须写明**票数分布**。没有票数的议会无法判定结果。

```
【议会】沈氏族老会，七人
【票型】三票在二叔手上；两票中立；两票支持沈砚（但不敢明说）
【通过门槛】四票
```

### 结构 D：无核心（网络）

没有明确头目，靠共同利益维系。

**特征**：打不死，但也做不成事。

**适用**：商帮、情报网、邪教。

**写法要点**：必须写明**联络方式**。没有联络方式的无核势力无法指挥。

## 三、关系的五个维度

`relation` 只写「态度 + 为什么」还不够。完整的势力关系要写五个维度：

| 维度 | 取值 | 判据 |
|---|---|---|
| **态度** | 依附 / 合作 / 中立 / 竞争 / 敌对 | 必须选一个 |
| **强度** | 1–5 | 5 = 不惜代价 |
| **原因** | 一件具体的事或一个具体的把柄 | 不能是「历史上不和」 |
| **公开度** | 公开 / 半公开 / 秘密 | 决定能不能在明面上动作 |
| **变化趋向** | 趋紧 / 趋缓 / 稳定 | 决定后文会不会爆 |

### 完整写法

```
【关系】陈留县衙 → 漕帮
  态度 竞争（强度 3）
  原因 漕帮封码头逼迫县衙减税；县衙握着漕帮走私盐的证据但不敢用（怕漕帮闹事）
  公开度 半公开（明面上互不干涉）
  趋向 趋紧（第 40 回县衙换新知县）
```

### 为什么需要「公开度」

**公开度决定「这件事能不能被主角利用」。** 敌对关系如果是秘密的，主角就没法拿它做文章；如果是公开的，主角可以当众挑拨。

### 为什么需要「变化趋向」

**趋向决定这条关系会不会变成剧情。** 三条「稳定」的关系永远是背景；一条「趋紧」的关系会在十几回后爆。

**判据：一本 100 回的书，至少要有 3 条「趋紧」的关系。** 少于 3 条，中后段没有冲突来源。

## 四、势力网络的三个必须

### 必须 1：每个势力至少有一条敌对关系

没有敌人的势力不会动。**判据：它会不会主动做事？** 只有敌对关系能推动它主动做事。

**例外**：纯功能性势力（只出场 1–2 回），可以只有一条依附关系。

### 必须 2：敌对关系必须成对

A 视 B 为敌，B 必须也有对 A 的关系条目。**且两者的强度不必相等。**

```
县衙 → 漕帮：竞争（强度 3）
漕帮 → 县衙：敌对（强度 4）  ← 漕帮更想动手
```

**强度不对称本身就是戏**：一方想打，一方想拖。

### 必须 3：必须有一个「主角能撬动的支点」

**判据**：主角能不能用一句话/一件事让某两个势力的关系变化？

- 能 → 势力网络是活的
- 不能 → 势力网络只是背景板

**支点的三种类型**：

| 支点 | 例 |
|---|---|
| **信息** | 主角知道 A 的把柄，可以卖给 B |
| **资源** | 主角手里有双方都要的东西 |
| **合法性** | 主角能让某个动作变成「合法的」或「非法的」 |

## 五、地理与势力的关系

### `controller` 必须分级

**判据：完全控制 / 部分控制 / 名义控制 / 争夺中。**

| 级 | 写法 |
|---|---|
| 完全 | 「城内四坊归县衙」 |
| 部分 | 「城西三坊实际归漕帮，县衙只管收税」 |
| 名义 | 「码头名义归县衙，实际漕帮说了算」 |
| 争夺 | 「第 30 回起，码头归属未定」 |

**「名义控制」是最有戏的一档**，因为它天然有张力。

### 地理必须能被行程验证

`position` 的距离必须与「驿马日行多少里」这条 rule 一致。

**判据：从 A 到 B 需要几天，能不能算出来？** 能 → 地理可用；不能 → 后面每一章的时间线都判不了。

## 六、五个常见的势力崩法

| 崩法 | 表现 | 修法 |
|---|---|---|
| **纸糊反派** | 反派势力很大但从不主动做事 | 给它一条「趋紧」的敌对关系 + 一个资源诉求 |
| **万能官府** | 官府什么都能管 | 分级 `controller`，写明管辖不到的地方 |
| **无限势力** | 一路打一路冒出更大的势力 | 上限：最强的已经出场，之后只有更小 |
| **无票议会** | 长老会投票但没写票数 | 补票型，写清门槛 |
| **关系单边** | 只有 A 恨 B，B 对 A 无条目 | 补双向 |

## 七、势力进剧情的四个接口

势力不写进剧情就只是设定集。四个接口：

### 接口 1：资源的争夺

**判据**：这个势力手里有什么主角需要的？写下来。

### 接口 2：规则的执行

**判据**：哪条 `rules.forbid` 由它执行？写下来（见 `references/rule-whitepaper.md` 类型 B）。

### 接口 3：身份的授予

**判据**：它能不能给主角一个身份（或收回）？能 → 它是关键势力。

### 接口 4：信息的垄断

**判据**：它知道什么别人不知道的？这是最常用的接口，也是最快能用的。
