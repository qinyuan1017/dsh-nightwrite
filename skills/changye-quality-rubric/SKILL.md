# 质量评审表

给一章一个**六维分 + 改进优先级**。分数是给决策用的，不是给安慰用的。

## 六个维度（各 0-10 分）

| 维度 | 问什么 | 数据来源 | 9-10 分的门槛 |
|---|---|---|---|
| **一致性** | 有事实冲突吗 | `changye-continuity-pass` 的判定 | 零致命，且警告 ≤2 条 |
| **角色** | 行为符合心理阈值与语言基因吗 | `ledger.get` 的 `characters` | 每句对白都能认出是谁说的 |
| **节奏** | 有推进点吗，有没有注水段 | 逐段标推进点 | 无连续 1500 字空转 |
| **伏笔** | 该收的收了没，新埋的有回收计划吗 | `foreshadow` 台账 | 应收全收，新埋全有 `payoffAt` |
| **钩子** | 章末想不想点下一章 | 末 150 字 | 属「新信息/急追问/动作悬停」三类之一 |
| **审美** | 句子是活的还是套的 | 风格卡对读 | 短句占比与比喻密度都在风格卡 ±30% 内 |

## 执行步骤

**第 1 步：先拿硬数据**

一致性分不许自己判——必须引用 `changye-continuity-pass` 的结论。没跑过就不许打这一维的分，写「未测」。

**第 2 步：逐维打分并给证据**

每一维的分后面必须跟一句「依据」。没有依据的分不算分。

**第 3 步：定门禁**

`project.get` 的 `qualityGate` 是及格线。规则：

- 任一维 < 门禁分 → 整体不通过
- 一致性维有致命 → 直接不通过，不看其他维
- 六维平均 ≥ 门禁且无单项 < 门禁-2 → 通过

**第 4 步：排改进优先级**

按「改一处的收益 ÷ 成本」排序，输出前三项。成本按改动量估：句子级 < 段落级 < 结构级。

**第 5 步：落盘**

`changye_op` → `problem.save`（把低于门禁的维度记成问题条目），让驾驶舱的欠账清单能看到。

## 输入

- 待评正文（`chapter.get`）
- `changye-continuity-pass` 的报告（一致性分的唯一来源）
- `ledger.get`（角色、伏笔）
- `project.get` 的 `qualityGate`（门禁线）
- 风格卡（审美分的基准）

## 输出格式

```
【总分】<n>/10 · 门禁 <n> → <通过 / 不通过（原因）>
【六维】
  一致性 <n> — 依据：致命 <n> / 警告 <n>（引用 continuity-pass）
  角色   <n> — 依据：<哪句对白不像他 / 哪处行为越界>
  节奏   <n> — 依据：推进点 <n> 个 / 最长空转 <n> 字
  伏笔   <n> — 依据：应收 <n> 收 <n> / 新埋 <n> 有回收计划 <n>
  钩子   <n> — 依据：属 <新信息/急追问/动作悬停/无效>
  审美   <n> — 依据：短句 <n>%（卡 <n>%）/ 比喻 <n> 处/千字（卡 <n>）
【改进优先级】
  1. <改什么> — 收益 <提哪一维多少分> — 成本 <句子/段落/结构级>
  2. …
【不建议改的】<得分够用、改了性价比低的维度>
```

## 检查清单

- [ ] 一致性分引用了 `continuity-pass` 的结论，不是自己判的
- [ ] 六维全打了分（或明确写「未测」及原因）
- [ ] 每一维都有具体依据，不是空分
- [ ] 门禁线取自 `project.get`，不是自己设的
- [ ] 「任一维 < 门禁-2 则不通过」的规则执行了
- [ ] 改进优先级按收益÷成本排过，只给前三
- [ ] 明确写了「不建议改的」维度
- [ ] `problem.save` 已记录低于门禁的维度

## 禁止事项

- 不许直接改稿。
- 不许替代 `changye-continuity-pass` 自己判设定冲突。
- 不许给「整体不错 7 分」这种无依据的总分。
- 不许所有维度都给同一个分数（那说明没分开看）。
- 不许把门禁线往下调来让这章通过。
- 不许只报分不报优先级——分数不能直接指导动作，优先级才能。
