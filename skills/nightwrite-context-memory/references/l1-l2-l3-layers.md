# L1 / L2 / L3 三层切分与取用

三层不是三种存储，是三种**取用策略**。同一份信息在不同的问题下属于不同层。搞错层的代价有两个：塞太多（挤爆窗口）和塞太少（写出矛盾）。

## 分层判据：一句话

```
问：这条信息，接下来 2000 字里会被用到几次？
  每次都用（人物身份、世界规则、本章目标）→ L1
  只在某一段用一次（原文语气、伏笔原句）→ L2
  只在讨论远期时才用（第 40 章发生了什么）→ L3
  一次都不用 → 不取
```

关键：**层由「本次使用频率」决定，不由「信息重要性」决定**。第 12 回的原文很重要，但你这次写第 80 回，它就不该占 L1。

## L1 常驻层

### 该放什么

L1 的唯一标准：**写这一章时，每次落笔都可能要参照的东西**。

| 类别 | 具体内容 | 压缩形式 |
|---|---|---|
| 本章目标 | 本章三件事（要变什么）、章末钩子 | 3 句 + 1 句 |
| 出场人物 | 只取本章出场者 + 直接被提到者，状态卡五字段 | 每人 ≤6 行 |
| 硬约束 | 世界规则里本章会碰到的 3–6 条 | 每条 1 句，写成禁令 |
| 已有伏笔 | 本章要埋/要收的，各 1–2 条 | 每条 1 句 |
| 上一章接口 | 上一章末 3 句发生了什么（不是原文） | 1 句 |
| 风格卡 | 句长区间、比喻密度上限、禁用词 | 3–5 行 |
| 读者画像 | 雷点 3 条、爽点 3 条 | 6 行 |

### 大小上限

L1 的硬上限：**能一次塞进上下文的 15–25%**。按一次对话 32k token 的预算算，L1 约 5k–8k token，中文约 4000–6000 字。

超过这个量 → 不是压缩问题，是**选取问题**：你把本章不用的东西塞进来了。

### 选取方法（防止 L1 膨胀）

按这个顺序，取够就停：

1. 本章三件事 + 章末钩子（必备，不可省）
2. 本章出场者的状态卡（**只取出场者**，不是全部角色）
3. 出场者之间、出场者与本章关键人物的关系（只取实际会用到的那几条）
4. 本章会碰到的世界规则（问：这章会不会违反某条规则？会 → 取那条；不会 → 不取）
5. 本章要埋/收的伏笔
6. 风格卡 + 读者画像（各压到最小）

### 常见错误

| 错误 | 症状 | 后果 |
|---|---|---|
| 塞全部角色卡 | 「我把所有人物都放进去了，保险」 | 挤掉世界规则和伏笔，写出来的章违反设定 |
| 塞全卷大纲 | 「万一要用」 | 模型被远期目标干扰，本章焦点散掉 |
| 塞上一章原文 | 「保持语气连贯」 | 吃 3000 字，只为取 3 句语气 |
| 只塞本章目标 | 「其他按需查」 | 写到中段出现矛盾，再回头查已经晚 |
| 塞账本原始 JSON | 「不加工直接用」 | 结构噪音占 60%，有效信息被淹没 |

**原则**：L1 是**加工过的**，不是原始数据的转储。原始数据在工具里，L1 是本次用的视图。

## L2 按需召回层

### 三种召回的取法与取量

| 需求 | 召回什么 | 取多少 | 为什么是这个量 |
|---|---|---|---|
| 接续语气 | 上一章末尾 | 200 字 | 语气节奏在 200 字内稳定，再多就是重复内容 |
| 伏笔兑现 | 该伏笔埋设处的原句 | 1–2 句 | 只需要「当时的措辞和细节」，不需要那一段 |
| 首次出场描写 | 该角色/地点首次出现的段落 | 1 段（≤300 字） | 确保外貌、称谓、特征不漂移 |
| 专名核对 | `terms` 里的确切写法 | 1 行 | 逐字，不许凭记忆 |
| 前文冲突核对 | 涉及冲突的那一句 | 1–2 句 | 判据是「原文怎么写的」，不是「大概写的什么」 |

### 召回的纪律

**每次召回必须记「为了什么」**。格式：

```
L2 召回：上一章末 200 字 → 为了接住「他把灯吹灭了」这个动作的语气
L2 召回：第 34 回「半枚虎符」埋设句 → 为了本章兑现时措辞一致
```

不记原因的召回 = 无目的读取，等于在烧预算换「感觉」。

**不许做的召回**：

- 整章读（除非做 `nightwrite-continuity-pass` 的六类扫描）
- 「读三五章找找感觉」——这是最贵的坏习惯
- 为了确认一个自己已经记得很清楚的事再读一遍（先写，写完再核）

### L2 的回收

L2 召回的内容用完就丢出上下文，不进 L1。唯一例外：如果这段内容**本章会反复用到**（比如一个核心场景的原始描写，本章要重写它），那它就该被提升进 L1。

## L3 摘要层

### 什么时候必须建

- **约 50 章之后必须有**（SKILL 定的门槛）
- 提前到 30 章的判据：单章平均 3000 字，30 章 = 9 万字，已经超出「凭记忆把握」的范围
- 到 100 章还没建 → 后续所有远期讨论都在靠猜，一致性会肉眼可见地衰减

### 摘要格式（三段式 + 钩子）

```
第 N 回 | <回目> | ① 起因：<一句> ② 变化：<一句> ③ 落点：<一句> | 钩子：<一句>
```

示例：

```
第 26 回 | 井台边的两只碗 | ① 起因：主角到驿舍投宿，主人不肯收 | ② 变化：主人认出他，说出自己儿子三年前失踪 | ③ 落点：主角答应替他找，换了住处 | 钩子：井台边有两只碗，主人说院子里只住他一个
```

### 摘要的写法纪律

| 规则 | 说明 |
|---|---|
| 只记事实 | 「他去了城西」是事实，「这段写得很压抑」是评论，不许进 |
| 每段一句 | 起因/变化/落点各一句，不许展开 |
| 钩子必记 | 钩子是下一章的回溯锚点，漏了就等于这一章的接口丢了 |
| 用角色名不用代称 | 「沈砚」不「她」，否则远期检索时对不上 |
| 专名按 `terms` | 逐字一致 |
| 长度上限 | 每章 60–100 字。超过 120 字说明在写剧情概述，不是摘要 |

### L3 的三种用途

1. **远期情节讨论**：问「第 40 章那件事的影响还在吗」→ 读 L3，不读原文
2. **一致性回溯**：发现矛盾时，用 L3 定位「这件事第一次出现在哪一回」，然后只召回那一章的 1–2 句原文（降到 L2）
3. **卷末复盘**：一卷写完后，用 L3 生成卷级摘要（每卷 200–300 字，供全书级讨论用）

### L3 的四级压缩（章数增长后的处理）

| 章数 | L3 形态 | 大小估算 |
|---|---|---|
| <50 | 不建 | — |
| 50–150 | 逐章摘要（每章 60–100 字） | 约 1 万字 |
| 150–400 | 逐章摘要 + 每 20 章一个块摘要（每块 150 字） | 约 2 万字 |
| >400 | 只保留块摘要 + 关键章逐章摘要（转折点、代价、结算章） | 约 1.5 万字 |

**关键章优先保留**：转折章、代价章、结算章、伏笔埋设章——这四类永不压缩。

## 判断该用哪一层：决策树

```
这个问题需要知道「具体怎么写的」？
  是 → L2（召回原句，1–2 句就够）
       例外：整段要重写 → 提升进 L1
  否 ↓
需要知道「当时到底发生了什么」？
  是 → L3（读该章摘要）
       找不到 → L1 有缺口，补进账本
  否 ↓
需要知道「现在是什么状态」？
  是 → L1（账本视图）
  否 → 这个问题不需要上下文，直接答
```

## 三层之间的升降规则

| 触发 | 动作 |
|---|---|
| L2 召回的内容本章反复用 | L2 → L1（写进本次的 L1 视图） |
| L1 里的某条信息本章一次没用 | 留在 L1（它是状态，下次还要用）；但如果是「本章专属」的临时项，用完删 |
| L3 某章被反复查 | 把该章的摘要细化到 150 字 |
| L3 摘要与 L1 账本冲突 | **以 L1 为准**（账本是结构化维护的，摘要是文本记录），并回查原文裁决 |
| 原文与 L1 冲突 | 以原文为准，改 L1，记 `ledger.upsert` 说明 |

## 预热检查（SKILL 第 1 步的展开）

每次开工按固定顺序，缺项点名：

| 顺序 | 拉什么 | 缺了怎么办 |
|---|---|---|
| 1 | `outline.get`：本卷结构 + 本回细纲 | 缺 → 不能开工，先去 `nightwrite-plan-novel` |
| 2 | `ledger.get`：八类中本章相关的 | 缺某类 → 记录缺项，写完后补 |
| 3 | `project.get`：`worldState`、`targetWords`、`qualityGate` | 缺 `targetWords` → 无法定篇幅，先补 |
| 4 | 风格卡 | 缺 → 按默认区间写（句长 14–22、比喻密度 ≤3），写完建议补卡 |
| 5 | 读者画像 | 缺 → 按通用网文标准，但不能据此判断雷点 |

**八类账本的完备度记法**：`ledger 3/8`（八类里齐了几类）。低于 5/8 时，本章的一致性风险已经很高，建议先补账本。

## 三层与 token 预算的配比

一次完整的写章对话，预算建议这样分：

| 用途 | 占比 | 说明 |
|---|---|---|
| L1 常驻 | 20–25% | 4000–6000 字 |
| L2 召回 | 10–15% | 每次 200–300 字，3–6 次 |
| L3 摘要 | 5–10% | 只读相关章，不读全书 |
| 本章生成与修改 | 50–60% | 主体 |

L1+L2+L3 超过 50% → 选取有问题，回上面的选取方法重来。
