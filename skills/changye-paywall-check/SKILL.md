# 付费卡点检查

只查一件事：**读者在掏钱那一刻，有没有得到「非付不可」的理由**。

## 三个卡点

| 卡点 | 位置 | 读者的心理问题 |
|---|---|---|
| **免费末章** | 最后一个免费章的末尾 | 「我非得看下一章吗」 |
| **付费首章开头** | 上架第一笔钱换的那 300 字 | 「我是不是被坑了」 |
| **关键悬念释放** | 付费区内最贵的那个悬念兑现处 | 「等了这么久就这」 |

## 执行步骤

**第 1 步：找卡点位置**

`chapter.list` 找免费/付费分界章（无元数据则按作者说明或常见 20-30 章估计，并注明「估计」）。

**第 2 步：查免费末章（最重要）**

三个必须：

1. **一个未落的动作**（正在发生，停下时还没结束）
2. **一个刚抛出、没解释的信息**
3. **一个明确指向下一章的因果**（不是「后来发生了很多事」）

三缺一 = 卡点弱；三缺二 = 卡点无效。

**第 3 步：查付费首章前 300 字**

读者刚付钱，最怕两件事：**回顾上一章**、**换视角讲别人**。这两件出现任何一件，首订体验就废了。

前 300 字必须：接着上一章的那个未落动作往下走，不许倒叙、不许换人、不许总结。

**第 4 步：查悬念释放的性价比**

问三个问题：

1. 这个悬念等了多久（从埋设到兑现的章数）？
2. 兑现时给了几条新信息（只给一条 = 亏）？
3. 兑现后有没有立刻接新悬念（没有 = 读者会在兑现处合书）？

等 30 章只兑现一条信息 = 严重不值。

**第 5 步：只评卡点，不评定价**

## 输入

- `chapter.list`（找分界章与章数）
- `chapter.get`（免费末章、付费首章、悬念兑现章）
- `ledger.get` 的 `foreshadow`（悬念的 `plantedAt` → `payoffAt` 跨度）
- 画像卡（付费动机决定「什么算值」）

## 输出格式

```
【分界】免费至第 <n> 回，付费自第 <n> 回（<实测/估计>）
【免费末章】风险 <低/中/高>
  未落的动作：<有/无 — 引用>
  未解释的信息：<有/无 — 引用>
  指向下一章的因果：<有/无 — 引用>
【付费首章前 300 字】风险 <低/中/高>
  是否回顾上一章：<是/否>
  是否换视角：<是/否>
  是否接住未落动作：<是/否>
【悬念释放性价比】
  悬念：<名>｜等了 <n> 章｜兑现给 <n> 条新信息｜兑现后接新悬念：<有/无>
  判定：<值 / 勉强 / 不值>
【改法方向】免费末 <方向>｜付费首 <方向>｜兑现处 <方向>
```

## 检查清单

- [ ] 明确了分界章，估计的已标注
- [ ] 免费末章三项逐项检查并引用
- [ ] 付费首章前 300 字查了「回顾」与「换视角」两个雷
- [ ] 悬念跨度用了 `foreshadow` 的真实章号
- [ ] 兑现处统计了新信息条数
- [ ] 查了兑现后是否接新悬念
- [ ] 只给方向，没给成稿
- [ ] 没有涉及定价

## 禁止事项

- 不许决定定价策略、章节切分方案（那是商业决策）。
- 不许查设定 Bug。
- 不许给改写稿。
- 不许因为「这里能卡住人」就建议把中间内容砍掉塞到付费区——那是欺骗，不是卡点。
- 不许在分界章不明时假装确定。
