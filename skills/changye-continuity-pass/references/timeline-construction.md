# 怎么建时间线

> 适用：需要判断时间冲突（`conflict-six-types.md` 类型一）时读这份；给出可操作的时间线表示法与对表方法。

时间线不是「按顺序复述发生了什么」。**时间线是每回的时间坐标，加上跨回事件的耗时账。** 没有坐标就没有时间冲突可比。

---

## 一、三层表示法

### 第 1 层：章级时间锚（每回一行）

每回必须能填出这一行：

```
第 N 回 | 绝对时间 | 跨度 | 开头状态 | 结尾状态
```

例：
```
第 7 回 | 三月十七，夜 | 一夜 | 三更到城外 | 天亮进山
第 8 回 | 三月十八，晨 | 半日 | 进山 | 午时到洞口
```

**绝对时间从哪来**：
1. `ledger.events` 的 `at` 字段（最权威）
2. 正文里的明确时间词（「三月十七」「三更」「第三天」）
3. 由前两回推算

三层来源冲突时，优先级：`events` > 正文明确词 > 推算。**但若 `events` 与正文明确词冲突，判为致命（账本与正文明文冲突），必须当场指出。**

### 第 2 层：场景级时刻（每回内）

一回内跨多个场景时，逐个场景给相对时间：

```
第 7 回
  场景 1（刚入夜）  出城，走三里
  场景 2（约一个时辰后）  到岔路，遇伏
  场景 3（夜半）  逃进破庙
  场景 4（四更）  对方追到
```

**场景间隔必须能相加到章级跨度**。上面四段：入夜→四更，约三到四个时辰，与「一夜」相符。

### 第 3 层：事件级耗时（跨回）

**这是判断「间隔不成立」的唯一依据**，也是最常缺的一层。

```
事件 | 发生回目 | 耗时 | 依据
从府城到青石镇 | 第 4 回 | 7 天 | 正文「走山路要七天」
三刀重伤恢复 | 第 5 回 | ≥10 天 | 无明文，按常识下限估
烧一封信 | 第 6 回 | 几分钟 | 常识
```

## 二、耗时的三种给法

### 2a. 明文给

正文/账本写「七天」「两个时辰」。最可靠，直接采用。

### 2b. 反推给

由行程长度 + 交通方式反推。

| 交通 | 日行 |
|---|---|
| 步行 | 30–40 里 |
| 快马 | 200–300 里（要换马，否则一日伤马） |
| 普通马车 | 60–80 里 |
| 船（顺水） | 100–150 里 |
| 船（逆水） | 20–40 里 |

**关键**：这些数字一旦在本书里被用过一次（无论谁用过），就成为本书基准，后文必须遵守。

### 2c. 常识下限给

伤情、孕产、饥饿、脱水、闭关。这类**只给下限，不给上限**。

| 伤情 | 下限 |
|---|---|
| 皮肉伤（可活动） | 3–5 天 |
| 见骨刀伤（不能提重物） | 15–30 天 |
| 内伤吐血（不能动武） | 1–3 个月 |
| 断骨（接好，能走） | 1–3 个月 |
| 濒死（清醒可行动） | 7–15 天 |

**判定「间隔不成立」**：如果两回之间的绝对时间差 < 常识下限，且正文没有交代「用了什么办法缩短」，判致命。

## 三、对表七步

1. **取范围**：本章（第 N 回）+ 前两回（第 N-2、N-1 回）。三回是判断顺序与间隔的最小窗口。
2. **列锚点**：给三回各填一行章级时间锚。填不出的，标「无时间锚」——这本身就是警告（读者会失去时间感）。
3. **排序列**：按绝对时间排序。若不单调（出现倒序），记「顺序颠倒」。
4. **算间隔**：相邻两回算 Δ。逐个查 Δ 与事件耗时是否相容。
5. **查标记**：本章所有时间词（季节/月/节令/时辰/更次）与绝对时间是否一致。
6. **查在场**：每个场景的在场人物，在时间顺序上是否可能（不能同一时辰出现在两地）。
7. **出结论**：顺序、间隔、标记三类各给数字。

## 四、五个高频时间漏洞

### 漏洞 1：「三天后」累积

每回都用「三天后」起头，二十回就是六十天。但正文里的季节没变（还是春天）。

**判法**：把所有「X 天后」累加，与季节/节令的变化比对。春天三个月 = 90 天，如果累计已 60 天，剩 30 天可写，写手必须知道。

### 漏洞 2：夜与昼的错位

上一回末尾是深夜，下一回开头是「日头正烈」，中间没有任何交代。

**判法**：章级时间锚的「开头状态」与上一回的「结尾状态」必须相容。

### 漏洞 3：一去一回只算单程

「走了七天才到」——回程又要七天。但下一回就写「他回来了」。

**判法**：所有位移必须算双程（除非明确写「不回来」）。

### 漏洞 4：同时发生的事件被写成先后

两条线并行，写手按「先写 A 线、再写 B 线」的顺序呈现，读者会以为是先后。

**判法**：如果两条线的绝对时间重叠，必须在正文里给**至少一处交叉锚点**（「同一时刻，另一处……」「那时她还不知道」）。没有交叉锚点 = 读者误读，判警告。

### 漏洞 5：更次与时辰混用

「三更」= 子时 = 23:00–01:00。「五更」= 寅时 = 03:00–05:00。写手常把「三更」当「凌晨三点」。

**对照表**（必须在本书内统一用一套）：

| 更 | 时辰 | 现代时间 |
|---|---|---|
| 一更 | 戌 | 19–21 |
| 二更 | 亥 | 21–23 |
| 三更 | 子 | 23–01 |
| 四更 | 丑 | 01–03 |
| 五更 | 寅 | 03–05 |

## 五、时间线表格模板

```
【范围】第 <N-2>–<N> 回

【章级锚】
| 回 | 绝对时间 | 跨度 | 开头状态 | 结尾状态 |
|---|---|---|---|---|
| N-2 | 三月十五，昼 | 一日 | 在城中 | 出城 |
| N-1 | 三月十六，夜 | 一夜 | 城外 | 到山口 |
| N | 三月十七，晨 | 半日 | 山口 | 洞外 |

【间隔核算】
N-2 → N-1：Δ = 1 日，事件耗时 = 出城 + 行 40 里（≈1 日）→ 相容
N-1 → N：Δ = 半日，事件耗时 = 上山（≈2 时辰）→ 相容

【时间标记】
本章出现：三月十七、晨、午时 → 与锚一致

【在场核查】
第 N 回场景 2：主角 + 阿禾 → 阿禾第 N-1 回末在城外，相容

【结论】
顺序 0 处 / 间隔 0 处 / 标记 0 处
```

## 六、账本缺时间数据时怎么办

`ledger.events` 为空或字段残缺时：

1. **不许**判「通过」。SKILL.md 明确：盲区只能是「警告 + 点名」。
2. 报告里写：`【审计盲区】events 类无数据，时间线仅按正文推算，基准可能不稳。`
3. 用正文第一次出现的时间为准，并在结论里注明「基准取自第 X 回正文」。
4. 建议补账（这是给账本岗的建议，不是你自己补）。
