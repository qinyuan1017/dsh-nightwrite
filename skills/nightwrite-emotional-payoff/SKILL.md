# 情绪回报检查

只查**欠账有没有还**。不设计新剧情、不改人设、不评价文笔。

## 三种情绪货币

| 类型 | 读者要什么 | 兑现动作 | 常见失败 |
|---|---|---|---|
| **爽点** | 压制反转（打脸/翻盘/被认可） | 让压制者当众失效 | 赢了但没人看见 |
| **虐点** | 心疼但不弃书 | 让角色失去具体东西，且他没得选 | 虐完没有承接，读者会走 |
| **甜点** | 关系推进 | 一次只有两人知道的靠近 | 表白即完结，没有后续张力 |

## 执行步骤

**第 1 步：建情绪账**

从 `chapter.list` + `chapter.get` 扫全文，列出每一处「埋了情绪欠账」的地方：

```
第 N 回：主角被当众羞辱（欠：爽点）
第 N 回：她替他挡了一刀（欠：甜点/虐点）
```

**第 2 步：查欠账时长**

```
欠账章数 = 兑现章 - 埋设章
```

| 类型 | 可忍章数 | 超了会怎样 |
|---|---|---|
| 爽点 | ≤5 章 | 读者会觉得窝囊，开始骂 |
| 虐点 | ≤3 章 | 憋屈转成厌烦 |
| 甜点 | ≤10 章 | 关系线会被遗忘 |

**第 3 步：查兑现质量（三种失败形态）**

1. **无人在场**：主角赢了，但该看见的人没看见 → 爽点归零。
2. **代价抵消**：赢了但立刻付出同等代价 → 读者会算成「白干」。
3. **兑现即结束**：甜点兑现后关系线立刻停止推进 → 张力消失。

**第 4 步：查延迟满足的合理性**

延迟满足只有两种情况是加分的：

- 延迟期间读者**持续获得小回报**（每 2-3 章给一点）；
- 延迟本身在**积累张力**（每一次拖延都让赌注变大）。

否则延迟就是拖。

**第 5 步：只报欠账与位置，不给新剧情**

## 输入

- `chapter.list` + 相关 `chapter.get`
- `ledger.get` 的 `conflicts`（冲突赌注）、`highlights`（已记录的高光）
- 画像卡（雷点/爽点决定什么算回报）

## 输出格式

```
【情绪账】
  第 <n> 回：<埋了什么>（欠：<爽/虐/甜>）→ 兑现：第 <n> 回 / 未兑现
  第 <n> 回：…
【超期欠账】
  · <哪条> — 已等 <n> 章（上限 <n>）— 风险：<读者会骂窝囊/憋屈转厌烦/关系线被遗忘>
【兑现质量】
  · 第 <n> 回 — <爽/虐/甜> — 形态：<无人在场 / 代价抵消 / 兑现即结束 / 健康>
【延迟满足评估】
  <哪段延迟> — 期间小回报 <n> 次｜赌注是否递增 <是/否> → <加分 / 拖>
【改法方向】<只给方向：某处应让谁在场 / 某处应停止加码>
```

## 检查清单

- [ ] 建了完整的情绪账，每条标了类型
- [ ] 每条算了欠账章数
- [ ] 对照了三类的可忍上限
- [ ] 每个已兑现的点都查了三种失败形态
- [ ] 延迟满足按两条标准评估过
- [ ] 只给方向，没有设计新剧情
- [ ] 没有改动人物设定

## 禁止事项

- 不许设计新剧情来制造爽点。
- 不许改人物设定（「让他变强就能打脸了」不行）。
- 不许为了「看起来不憋屈」把虐点提前兑现——虐点的价值就在憋。
- 不许把「读者会生气」当成失败。读者生气但继续看，是好虐点。
- 不许忽略「无人在场」这种最隐蔽的失败——它让所有爽点白写。
