- `references/opening-three-moves.md` —— 章首的三种开法：动作切入/信息切入/状态切入，各给适用章型与失效形态
- `references/information-release-rhythm.md` —— 一章内信息释放的节奏：什么时候给、给多少、留多久，配比与判据

# 章节钩子

只设计**信息与悬念的投放位置**，不动主线因果、不查设定。

## 执行步骤

**第 1 步：定这一章要读者带走什么**

从 `outline.intent` 读 `hook`，判断它属于哪一类「带走物」：

| 类型 | 读者离开时的状态 | 适合 |
|---|---|---|
| **新信息** | 刚知道一件还来不及消化的事 | 悬疑、权谋 |
| **急追问** | 有一个必须马上回答的问题 | 追凶、解谜 |
| **动作悬停** | 一个正在发生的危险停在落下前一秒 | 动作、战斗 |
| **情绪欠账** | 欠了一个情绪要还（该报的仇没报） | 虐恋、复仇 |

四类都没有 → 这章的钩子是虚的，先回去改 `outline.intent`。

**第 2 步：开头 300 字三件事**

前 300 字必须完成：**给一个具体场景**（不是天气）、**给一个正在进行的动作**（不是回忆）、**埋一个不对劲**（读者感觉到但说不出）。三件缺一，开头就是平推。

**第 3 步：排信息释放节奏**

把这一章要知道的信息列出来，每条标：
- **给法**：直给 / 藏一半 / 让人物说漏嘴 / 只给现象不给解释
- **位置**：第几段给

规则：**同一段最多给一条新信息**；连续三段纯给信息 = 读者会跳过。

**第 4 步：写章末（最后 150 字）**

- 有效：停在动作落下前 / 停在一句话的中间 / 停在刚发现的那一刻。
- 无效：总结本章 / 宣布下章 / 抒情收尾 / 「欲知后事」。

**第 5 步：自检三问**

1. 把最后 150 字单独拿出来读，想不想翻下一章？
2. 把前 300 字单独拿出来读，知不知道这是在哪、在干什么？
3. 中间有没有连续 1500 字什么都没变？

## 输入

- `outline.intent`：本回 `summary` 与 `hook`
- `chapter.get`：待调整的正文（改开头/章末时）
- `outline.get`：下一回的 `summary`（章末钩子必须能接上下一回开头）

## 输出格式

```
【带走物】<新信息 / 急追问 / 动作悬停 / 情绪欠账> — <一句说明>
【开头 300 字】
  场景：<给什么>
  动作：<谁在做什么>
  不对劲：<读者感到的异样>
  现状诊断：<现在的开头缺哪一样 / 已满足>
【信息释放表】
  第 <n> 段 — <信息> — 给法 <直给/藏一半/说漏嘴/只给现象>
  第 <n> 段 — …
【章末设计】
  现末段：<引用>
  问题：<虚在哪>
  建议末段方向：<停在哪一刻>（只给方向，不给成稿）
【接续检查】下一回开头是 <…>，本章末钩子能否接上：<能/不能 + 原因>
```

## 检查清单

- [ ] 带走物属于四类之一，说得出是哪一类
- [ ] 开头 300 字三件事逐项检查过
- [ ] 信息释放表列了每条信息的位置和给法
- [ ] 没有连续三段纯给信息
- [ ] 章末不是总结/预告/抒情
- [ ] 章末能接上下一回开头
- [ ] 中部检查过有没有连续 1500 字空转
- [ ] 只给方向没给成稿

## 禁止事项

- 不许改主线因果。钩子只能调整「在哪一刻停」，不能改「发生了什么」。
- 不许查设定 Bug。那是 `changye-continuity-pass` 的活。
- 不许直接给成稿段落。给方向和「停在哪一刻」，落地由写手执行。
- 不许用「留个悬念」当设计。悬念必须是具体的某个问题或某个未落的动作。
- 不许把每章都设计成同一类钩子。连续三章同类型 = 读者会疲劳。
