> 适用：模拟评论写完了，要从里面挑出「真正会让人走」的那几条，而不是把最响的抱怨当成结论时读这份。

# 共识问题识别与流失判定

模拟评论的产物不是评论列表，是**三到五条共识问题 + 每条的影响判级**。这份讲怎么从 15 条评论里筛出这几条。

## 第一步：把评论转成「问题条目」

每条评论先剥掉情绪，写成一个**可命名的问题**。

```
原评论：「第 3 段那个换药写了两百字，结果伤情一点没变，白看。这章 3400 字至少 600 字可以删。」
问题条目：换药场景无功能推进（无效篇幅 600 字 / 3400 字 = 18%）
```

```
原评论：「看到第 6 章弃了，主角一直在挨打」
问题条目：前 6 章无有效反击（爽点缺位）
```

**命名规则**：`<位置/对象> + <缺陷类型> + <可量化的量>`

- 有量化的尽量量（字数、章数、段数、比例）
- 量不出来的，用二元描述（有/无、前/后不一致）

**一个问题条目只描述一件事**。如果一条评论里含两件事，拆成两条。拆得越细，越容易发现哪些是共识。

## 第二步：按「问题条目」聚合，不按评论聚合

同一件事被不同话说出来，要能认出来是同一件。

| 评论 | 表面说法 | 归一后的问题 |
|---|---|---|
| 路人：「主角太弱了」 | 抱怨强度 | 前 6 章无有效反击 |
| 核心读者：「他一直被压着，看得难受」 | 情感表述 | 同上 |
| 付费读者：「一章三千字全是铺垫，没打脸」 | 性价比 | 同上 |
| 挑剔读者：「主角的每次尝试都以失败告终，缺乏小胜节点」 | 术语 | 同上 |

**四条不同的话 = 一个共识问题，被 4 类提到**。

聚合时问：「这句话在抱怨哪个具体的东西？」东西相同就是同一条。

## 第三步：判共识（≥3 类）

SKILL 定的判据：**3 类以上读者同时提到 = 共识问题**。

执行细节：

- 数的是**类数**，不是条数。核心读者写 5 条同一件事的抱怨，仍然算 1 类
- 4 类全中 → 强共识，几乎必然是真问题
- 3 类 → 共识，进报告
- 2 类 → 记为「潜在」，单独列一节，不进共识
- 1 类 → 只在该类内部成立，不进报告（除非是核心读者的考据型，见下文）

**唯一例外**：核心读者的**考据型**发言如果只有它一类提到，但指向的是**事实矛盾**（前文写过 A，这章写成非 A），这一条必须进报告——因为它是硬 Bug，不需要共识来验证。这类问题应同时转给 `changye-continuity-pass`。

## 第四步：判影响（会走 / 会骂但继续）

这是整个流程里最重要的一步，也是最容易被跳过的一步。**共识 ≠ 会走**。

### 三档判据

| 档 | 判据 | 处置 |
|---|---|---|
| **会走**（红） | 触发了该类读者的**离开条件**，且这个条件在本章之前没被触发过 | 必须改 |
| **会骂但继续**（黄） | 抱怨的是长期存在的问题，读者已经忍了很久，但还在追 | 记录，不急改 |
| **只是响**（灰） | 挑剔读者/核心读者的高标准抱怨，与真实流失无关 | 不改 |

### 各类读者的离开条件（具体到可判）

**路人**：他没有任何沉没成本，离开条件是**任何一项**：

- 前 300 字没有具体场景/动作/异样（三招缺一即走）
- 第 1 章结束不知道主角要干什么
- 第 1 章没有让他产生「然后呢」的问题
- 出现他不认识的专名超过 5 个且没有解释

**路人只要触发一项就走，且不会再回来。** 他的抱怨最轻（一句「弃了」），但准确度最高。

**核心读者**（追 50 章以上）：

- 人物崩了（口吻漂移、能力漂移、道德漂移无代价）
- 设定矛盾（前文写过的事被推翻）
- 他喜欢的角色被**无意义地**写死或写废（有意义的不算）
- 作者的更新承诺被反复打破（不是本章的问题，但会在这章的评论里爆发）

核心读者**很少真的走**，但他们一旦走，会带走评论区的一部分氛围。所以他们的离开条件是「累计三次」——单次抱怨通常是黄档。

**挑剔读者**：他们几乎不走（走了就没有批评的对象了）。他们的「弃了」多数是假的。**不要为挑剔读者改稿。**

**付费读者**：

- 连续 3 章没有情绪回报（爽/虐/甜任何一种都没兑现）
- 付费卡点断在无意义处（这章结束在「他走进院子」，下一章整章是院子描写）
- 首订章的承诺（钩子）在 5 章内没有回应
- 同等价位下明显的替代品更好（这是外部因素，但会在评论里出现）

付费读者的离开是**永久**的，且会在评论里留下明确通牒（`再看两张，不行就撤`）。**这类通牒必须当红色处理**。

## 第五步：报告输出

```
【声明】以下为模拟，不代表真实读者数据
【共识问题】（≥3 类提到）
  1. 前 6 章无有效反击（爽点缺位）
     提到者：核心 / 路人 / 付费
     量：前 6 章共 6 次尝试，0 次成功，最长连败 6 章
     影响：红（会走）— 路人已触发「第 1 章不知道主角要干什么」；付费读者连续 6 章无情绪回报
     建议动作：第 3 章插入一次小胜（不需要改主线，把一个既有的失败改成「失败但拿走了东西」）
  2. 换药场景无功能推进
     提到者：付费 / 挑剔
     影响：黄（会骂但继续）— 单章无效篇幅 18%，未达付费读者的 3 章阈值
     建议动作：压缩 300 字，不重写
【潜在问题】（2 类提到）
  · <问题> — 提到者：<> / <> — 观察下一章是否升级为共识
【只是响】（不进共识，明确建议不改）
  · <挑剔读者的术语型批评> — 理由：其判据是文学标准，与本书定位不符
【最会走的一类】<哪类> — 因为 <触发了哪条离开条件>
【不做的事】本报告不含改写稿；落地请走 changye-revision-pass
```

## 「骂得响」与「真的会走」的分离技术

三种可操作的分离方法：

### 方法一：看这条抱怨有没有「继续看」的痕迹

如果评论里出现了对**后续内容**的期待（「不知道他下次能不能赢」「求别再虐了」），这个人不会走——他已经在想后面的事了。

如果评论里全是**对已读内容的清算**（「前面第 X 章就……这章还……」），这个人正在整理离开的理由。

### 方法二：看抱怨指向的是「这章」还是「这书」

- 指向这章（`这章有点水`）→ 黄档，读者还在
- 指向这书（`这书写得越来越差`）→ 红档信号，但注意：这可能只是这一章触发了他长期的不满，真正的问题是前面某章

**回溯规则**：出现「越来越」类表述时，往前找第一次出现同类抱怨的章号，那个位置才是真正的问题点。

### 方法三：看抱怨的数量与章号的关系

同一类抱怨在新章节出现时**减少** → 问题在改善，读者在适应
同一类抱怨在新章节出现时**增加** → 恶化中，红档
同一类抱怨**突然消失** → 最危险：这些人已经走了，不再评论

## 共识问题的排序算法

报告里按这个权重排序，不按条数：

```
优先级 = 类数权重 × 3 + 影响权重 × 5 + 可改成本系数
```

其中：

- 类数权重：4 类 = 3，3 类 = 2
- 影响权重：红 = 3，黄 = 1，灰 = 0
- 可改成本系数：局部改（压缩/替换）= 1，需补场景 = 0.5，需改主线 = 0（改主线的问题不进本轮修，单独立项）

**示例**：
- 前 6 章无有效反击：3 类 × 3 + 红 3 × 5 + 0.5 = 9 + 15 + 0.5 = 24.5
- 换药无功能：2 类 × 3 + 黄 1 × 5 + 1 = 6 + 5 + 1 = 12

按分数降序排，前 3 条进「本轮必修」，其余进观察。

## 常见误判

| 误判 | 后果 | 纠正 |
|---|---|---|
| 把挑剔读者的长评当最大问题 | 改完书变难看 | 挑剔读者权重降到路人之下 |
| 把核心读者的抱怨当流失信号 | 白改一堆细节 | 核心读者要累计三次才红 |
| 只看「骂得最狠」的那条 | 漏掉路人一句「弃了」 | 路人的一句话单独列一栏，强制看 |
| 把「卡在这儿，作者你没有心」当抱怨 | 改掉最好的卡点 | 这是付费认可的最高级形态 |
| 共识问题给了改法 | 越权 | 只报问题 + 建议动作方向，落地走 revision-pass |
| 同一个问题拆成多条统计 | 类数虚高 | 按「抱怨的是哪个东西」聚合 |
