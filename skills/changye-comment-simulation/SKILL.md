# 评论区模拟

模拟四类读者的发言，**提取共识问题**。产物是「他们会说什么」+「哪个问题是共识」，不是一份评价。

## 四类读者

| 类型 | 特征 | 发言风格 |
|---|---|---|
| **核心读者** | 追了 50 章以上，认设定认人物 | 护书，但细节斤斤计较 |
| **路人** | 首页点进来，看前 3 段决定走留 | 一句话定生死，不看解释 |
| **挑剔读者** | 专门找逻辑漏洞发长评 | 引用原文逐条拆 |
| **付费读者** | 花了钱，对性价比敏感 | 「这章值不值这个钱」 |

## 执行步骤

**第 1 步：先声明这是模拟**

报告开头必须写「以下为模拟，不代表真实读者数据」。这一步不许省。

**第 2 步：按四类各写 3-5 条评论**

每条必须：
- 有具体指向（引用某段某句或某个情节）；
- 用该类读者的真实语感（路人一句话、挑剔读者带引用）；
- 不写「很好」「不行」这种无指向评价。

**第 3 步：提取共识问题**

一条问题被 **3 类以上读者**同时提到 = 共识问题。共识问题和评论条数分开统计。

**第 4 步：区分「骂得响」和「真的会走」**

- 挑剔读者的长评往往最响，但不一定代表流失；
- 路人的一句话最轻，但最接近真实流失。

在报告里分开标注：**会走的** / **会骂但会继续看的**。

**第 5 步：只报问题，不改稿**

## 输入

- 待评正文（`chapter.get`）
- 画像卡（雷点/爽点用来判断哪些评论真会发生）
- `outline.intent`（判断「没看懂」是不是细纲本来就要藏）

## 输出格式

```
【声明】以下为模拟，不代表真实读者数据
【核心读者】
  · 「<评论>」 → 指向：<第 X 段/某情节>
  · …
【路人】
  · 「<评论>」 → 指向：<…>
【挑剔读者】
  · 「<评论>」→ 引用：「<原文≤15字>」→ 问题：<…>
【付费读者】
  · 「<评论>」 → 指向：<…>
【共识问题】（≥3 类提到）
  1. <问题> — 提到者：核心/路人/挑剔 — 影响：<会走 / 会骂但继续>
【最会走的一类】<哪类读者最可能因此离开> — 因为 <…>
```

## 检查清单

- [ ] 报告开头有「模拟」声明
- [ ] 四类各写了 3-5 条，没有只写一类
- [ ] 每条评论都有具体指向（段号或引用）
- [ ] 语感区分为四类（路人一句话、挑剔带引用）
- [ ] 共识问题按「≥3 类」筛过
- [ ] 区分了「会走的」和「会骂但继续看的」
- [ ] 没有改稿

## 禁止事项

- 不许代替真实读者数据下结论。
- 不许改写正文。
- 不许把模拟评论当成事实汇报给作者（必须带声明）。
- 不许只写好评或只写差评（四类读者必然分歧）。
- 不许把「我觉得会有人不喜欢」写成一条评论——必须有具体指向。
