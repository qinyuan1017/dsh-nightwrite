> 适用：要建画像卡、或者画像卡写了但「改稿时不知道按谁的口味」时读这份，取九项字段的可判定写法与自检。

# 画像卡九项的可判定写法

画像卡不是市场调研，是**判据表**。九项里每一项的功能都是：拿到一段正文，能用它判出「这一段对本书的目标读者是加分还是致命伤」。

**总判据**：一项写完之后，能不能拿它去判一段具体正文？

- 能 → 这一项合格
- 只能点头说「对，我们是写给这种人看的」→ 空标签，重写

## 项一：目标读者

### 三个必须具体的维度

| 维度 | 空标签 | 可判定写法 |
|---|---|---|
| 年龄段 | 「年轻人」 | 「22–32 岁」 |
| 性别倾向 | 「男女都看」 | 「男性为主（约 7:3），女性读者集中在情感线」 |
| 阅读资历 | 「老书虫」 | 「读过 20 本以上同类型，对境界/官制体系熟到能挑错」 |

**为什么资历必须写**：「读过 20 本」的读者和「刚开始看」的读者，对同一个套路的反应完全相反——前者觉得「又是这个」，后者觉得「好新鲜」。

**资历的量化方式**：用「能不能挑错」来定。

| 资历 | 判据 |
|---|---|
| 新读者 | 不知道这个类型的常见套路，需要解释 |
| 一般读者 | 知道套路但不追究，看执行 |
| 老读者 | 知道套路，且会主动检查作者有没有偷懒（境界跳级、官制错、时间线乱） |

**这三档决定一件大事**：设定要解释到什么程度。给老读者解释基础设定 = 侮辱；给新读者不解释 = 看不懂。

### 常见错误

- 「18–45 岁」→ 区间太宽，等于没说（这个区间的阅读场景、耐心、雷点完全不同）
- 「男女通吃」→ 通常是作者希望，不是实际。判据：书里的情感线占比和爽点类型，天然偏向一边
- 只写年龄不写资历 → 最重要的维度缺失

## 项二：阅读场景

### 场景决定三个物理参数

| 场景 | 单次阅读时长 | 单章字数上限 | 段落行数上限 |
|---|---|---|---|
| 通勤（地铁/公交） | 8–15 分钟 | 2000–3000 字 | 4 行 |
| 睡前（床上） | 20–40 分钟 | 3000–5000 字 | 6 行 |
| 摸鱼（上班间隙） | 3–8 分钟，频繁打断 | 1500–2500 字 | 3 行 |
| 蹲坑/排队 | 5–10 分钟 | 2000–3000 字 | 3 行 |
| 整块时间（周末/假期） | 1 小时以上 | 5000 字以上可接受 | 8 行 |

**换算依据**：中文阅读速度约 400–600 字/分钟（网文，非精读）。8 分钟 ≈ 3200–4800 字，但通勤有换乘打断，实际有效阅读按 60% 算 ≈ 2000–3000 字。

**段落行数的意义**：手机屏幕通常显示 12–18 行。段落超过 6 行，读者会在段落中间失去位置；超过 8 行必然被跳读。

### 场景混用时的处理

一本书通常有多个场景。写法：

```
主场景：通勤（60%）→ 单章 2000–3000 字，段落 ≤4 行
次场景：睡前（30%）→ 可接受 3000–4000 字
边缘：整块时间（10%）→ 为这部分读者准备的深度场景放这里
```

**决策规则**：按**主场景**定参数，不为边缘场景妥协。因为主场景占多数阅读量。

### 常见错误

- 「碎片时间」→ 不是场景，是形容。碎片时间有 30 秒（等电梯）和 20 分钟（通勤）两种，物理参数完全不同
- 场景与单章字数脱节（写「通勤阅读」但单章 5000 字）→ 卡是假的

## 项三：雷点

### 可判定的写法

每条雷点必须能对应到**正文里的一个可观察现象**。

| 不可判定 | 可判定 |
|---|---|
| 「不喜欢虐」 | 「主角连续 3 章无反击就弃」 |
| 「不喜欢啰嗦」 | 「连续两段环境描写就跳读」 |
| 「讨厌圣母」 | 「主角救一个刚害过他的人，且没有代价，会骂」 |
| 「不喜欢后宫」 | 「主角与超过 2 个异性有暧昧且不选，会弃」 |

### 雷点的三个层级

| 层级 | 含义 | 数量 |
|---|---|---|
| 一级雷点 | 出现就走，无商量 | 1–2 条 |
| 二级雷点 | 出现会骂，连续出现会走 | 2–3 条 |
| 三级雷点 | 出现会不适，但能忍 | 3–5 条 |

**画像卡至少写 3 条**（SKILL 的要求），建议按「1 条一级 + 2 条二级」起步。

### 雷点的来源

不许凭想象。三个来源：

1. **同类作品的差评区**（这个类型的读者最常骂什么）
2. **自己的前作评论**（若有）
3. **这个类型的结构性雷点**（如男频的「主角被绿」、女频的「男主不洁」）

判据：这条雷点，你能指出**至少一个具体的同类作品**因为踩它被骂吗？指不出 → 可能不是真雷点，是你自己的担心。

## 项四：爽点

### 与雷点对称的写法

| 不可判定 | 可判定 |
|---|---|
| 「喜欢爽」 | 「主角当众打脸，且被打脸者是有权力的一方，会追」 |
| 「喜欢甜」 | 「两人有只有彼此知道的小秘密，会反复回看」 |
| 「喜欢烧脑」 | 「一条线索在 3 章后被证明是误导，会觉得爽」 |

### 爽点的类型对应

| 情绪需求（项八） | 对应的爽点类型 |
|---|---|
| 解压 | 打脸、逆袭、扮猪吃虎 |
| 代入 | 被认可、被需要、被偏爱 |
| 智力快感 | 布局、反杀、伏笔回收 |
| 情感代偿 | 被无条件接纳、关系确认 |

**爽点必须与情绪需求对得上**。写「喜欢烧脑」但爽点全是打脸 → 画像内部矛盾，说明其中一项是作者的期望而非读者的实际。

### 常见错误

- 爽点写成了「这本书的优点」（「设定新颖」不是爽点，爽点是读者的情绪反应）
- 爽点太多（写 8 条）→ 等于没有优先级。3–5 条，按强度排

## 项五：耐心阈值（三个数字）

SKILL 要求三个数字。三个数字各自的依据：

### 数字一：能忍多少字没有推进

```
无推进可忍字数 = 单章字数 × 0.3 ~ 0.5
```

| 读者资历 | 系数 |
|---|---|
| 新读者 | 0.2（600 字无推进就走） |
| 一般读者 | 0.35 |
| 老读者 | 0.5（1500 字无推进能忍） |

**依据**：老读者有沉没成本，且相信作者在铺。新读者没有。

### 数字二：章末钩子无效连续多少章会弃

| 阅读频率 | 可忍章数 |
|---|---|
| 追更（每天看） | 2–3 章 |
| 攒更（一周看一次） | 5–8 章（因为一次看很多，单章钩子不重要） |
| 完本读者 | 不适用（他不看钩子） |

**这是最容易被忽略的一项**：追更读者和攒更读者对章末钩子的敏感度差 3 倍。画像必须写清是哪种。

### 数字三：单章超过多少字会跳读

由项二的场景决定（见上表）。

**这三个数字合起来是一个「耐心预算」**。正文超出任何一项，就触发了该读者的流失机制。

## 项六：付费动机

### 四种动机的判据

| 动机 | 读者的自我陈述 | 对内容的要求 |
|---|---|---|
| 追连载 | 「想看后面怎么样」 | 每章必须有新推进；断更杀伤力最大 |
| 看结局 | 「想知道最后怎样」 | 允许中间慢，但必须有明确的终点感 |
| 追作者 | 「这个作者写的我都看」 | 风格稳定比情节重要；换类型会掉一半 |
| 社交 | 「群里都在讨论」 | 需要有可讨论的点（争议、悬念、人物站队） |

### 判定方法

**不许猜**。三个可用的判据：

1. **同类作品的付费转化形态**：追更型作品的日更压力最大，说明读者是「追连载」；完本后才火的，说明读者是「看结局」
2. **本书的章末钩子密度**：如果作者自然地在写强钩子，说明他直觉认为是追连载读者
3. **评论区的语言**：出现「什么时候更新」→ 追连载；出现「结局是什么」→ 看结局

### 动机决定的一件事：断更的代价

| 动机 | 断更 3 天的后果 |
|---|---|
| 追连载 | 掉 20–40% 追读 |
| 看结局 | 影响小，但会攒着看 |
| 追作者 | 影响小，会等 |
| 社交 | 掉得最快（话题断了下沉） |

## 项七：替代品

### 为什么要写 3 个

读者的时间是有限的。他不看你的书时，在做别的事。**写不出替代品，说明这本书没有明确的竞争位置**。

### 可判定的写法

| 部分 | 写法 |
|---|---|
| 类型 A | 「同类型的头部作品」——读者会拿它比设定和爽点密度 |
| 类型 B | 「隔壁类型的替代」——读者在等更时会转去的那种 |
| 类型 C | 「非小说的替代」——短视频/游戏/剧集（这是真实的最大竞争者） |

**类型 C 必须写**。这是最容易被忽略的一项：读者的真正替代品往往不是另一本书，是刷短视频。

### 差异化必须写成一句话

```
本书的差异化：<读者从别处拿不到的那个东西>
```

合格：「同类作品里没人写漕运细节，本书的每一场冲突都长在漕运流程上」

不合格：「文笔更好」「设定更严谨」（这两个读者无法验证，也不会为了它换书）

**判据**：这句差异化，能不能让一个正在读替代品 A 的读者产生「那我去看看」的念头？不能 → 差异化不成立。

## 项八：情绪需求

### 四种需求与判定

| 需求 | 读者的行为特征 | 判定线索 |
|---|---|---|
| 解压 | 追更快、弃书快、不喜欢停顿 | 看书时在通勤/摸鱼，需要即时反馈 |
| 代入 | 会反复看某几段、会代入角色发言 | 评论区用「我」而不是「主角」 |
| 智力快感 | 会分析、会写长评、会挑逻辑 | 会指出伏笔和推理链 |
| 情感代偿 | 对角色关系投入极深、会为角色争论 | 评论区大量角色站队 |

**一本书通常有一个主需求 + 一个次需求**。写两个就够，写四个等于没有。

### 常见错误

- 「想让读者觉得深刻」→ 这是作者的期望（SKILL 明确禁止）
- 「既能解压又能烧脑」→ 这两个需求对内容的要求相反（解压要快、烧脑要慢），不可能同时满足

## 项九：弃书触发（三级）

SKILL 要求分三级。三级的判据必须可区分：

| 级别 | 读者行为 | 判据（可观察） |
|---|---|---|
| 一级 | 皱眉但继续 | 会跳过某些句子，但不影响理解 |
| 二级 | 开始跳读 | 跳过整段，且后续能靠猜接上 |
| 三级 | 直接退出 | 停止阅读，不再回来 |

### 三级必须递进且同类

**错误写法**（三级不相关）：

```
一级：主角太弱
二级：配角太多
三级：更新太慢
```

这是三个不同的雷点，不是同一件事的三个程度。

**正确写法**（同一件事的递进）：

```
一级：主角被压制超过 2 章（皱眉，但相信后面会翻）
二级：主角被压制超过 5 章且没有小胜（开始跳读打斗段）
三级：主角被压制超过 10 章，或者压制者是无名小角色（退出）
```

**判据**：三级的递进关系，能不能用「同一件事 + 时间/程度」串起来？不能 → 重写。

## 画像卡的落盘与引用

写进 `ledger.upsert`（kind=`highlights`，`name='读者画像'`）。

**为什么放 highlights**：它是全局参照物，不是情节账。但放在这里，`nightwrite-reader-report`、`nightwrite-drop-off-check`、`nightwrite-paywall-check` 都能通过同一个 `ledger.get` 拿到。

**引用时必须带版本**：画像卡改了（比如发现读者其实是攒更型），旧报告的依据就失效了。所以改动要在 `note` 里记「第 N 回修订，原因：……」。

## 九项自检表

```
- [ ] 目标读者：年龄区间 ≤15 岁跨度，写了资历档（新/一般/老）
- [ ] 阅读场景：主场景明确，且单章字数、段落行数与场景匹配
- [ ] 雷点：≥3 条，每条能对应一个正文可观察现象，且有一级雷点
- [ ] 爽点：3–5 条，与情绪需求对得上
- [ ] 耐心阈值：三个数字，各有推导依据
- [ ] 付费动机：四选一，有判定依据（不是猜的）
- [ ] 替代品：3 个类型，含非小说替代，差异化一句话可验
- [ ] 情绪需求：主 + 次，各一个，不矛盾
- [ ] 弃书触发：三级同类递进
```

九项缺一项不算卡（SKILL 的硬规则）。

## 一个反直觉的结论

**画像卡最重要的不是「写给谁」，是「不写给谁」。**

九项里有五项（雷点、耐心阈值、弃书触发、替代品、情绪需求）本质上都在划定**排除范围**。作者的本能是扩大受众（「男女通吃」「老少皆宜」），但每一项扩大的代价都是：判据变模糊，改稿时无从上手。

一本能明确说出「这本书不适合 X 类读者」的书，改起来有方向；一本「什么读者都适合」的书，任何改法都无法验证对错。
