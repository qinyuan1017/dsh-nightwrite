# 一章开工前的检查清单

门禁（`outline.intent` / 上一回结尾 / `ledger`）是「有没有」。这份是「能不能用」。**任何一项不过，停下来补料，不许用「先写着看」绕过。**

---

## A. 细纲侧（4 项）

### A1. 三件事是不是三种不同类型的「变化」

细纲写「这一回发生三件事」，但这三件事必须分别落在不同类别上。同一类别重复三次 = 其实只有一件事。

**变化七类**（本章至少覆盖三类）：

| 类别 | 问 | 例 |
|---|---|---|
| 目标变化 | 人物想要的东西变了吗 | 从「活下去」变成「带她一起活」|
| 风险变化 | 危险变大或变小了吗 | 从被一人追变成被一城人追 |
| 信息变化 | 读者/人物知道了什么新东西 | 知道父亲是被人杀的 |
| 关系变化 | 谁和谁的位置变了 | 从主仆变成共谋 |
| 资源变化 | 手里多了或少了什么 | 丢了令牌，得了证据 |
| 身份变化 | 别人怎么看他变了 | 从逃犯变成县令 |
| 立场变化 | 他对某件事的态度变了 | 从不肯杀人到肯 |

**判法**：把三件事各标一个类别。三类全同 → 退回 `nightwrite-plan-novel` 重写这一回的 `summary`。两同 → 允许，但要求第三类是本回的主要推进。

### A2. `hook` 是否能在 150 字内落地

拆 `hook` 的句子成分。如果它需要一整个场景（打斗、对峙、揭穿）才能落地，那就是**下一章的事**，不是钩子。

**可落地钩子的判法**：能用一句话写出来，并且这句话不超过 40 字。

- 可落地：「他说完这句，把刀递过来。」
- 不可落地：「主角与反派决战，最终反败为胜。」——这是下一章的剧情，不是钩子。

不可落地 → 报「hook 不可落地」，建议改成动作悬停型（见 `hook-types.md`）。

### A3. 细纲有没有和 `ledger` 明文冲突

逐条拿三件事去比 `ledger` 的 `rules`（能力上限）和 `foreshadow`（应收的伏笔）。

- 细纲要写的某个能力超出 `rules.allow` → 停，报「需先改 rules」，不许在正文里偷偷放宽。
- 细纲这一回正好落在某条伏笔的 `payoffAt` 上，但 `summary` 里没有回收动作 → 停，报「伏笔未排入」，交回 `nightwrite-plan-novel`。

### A4. 三件事的顺序是否就是因果顺序

判法：把三件事写成「因为 A，所以 B，因为 B，所以 C」。如果某个连接词换成「然后」才通顺，说明那两件事之间没有因果，只是并列。

并列不是错，但**并列的事件必须有同一个落点**（都在把人推向同一个决定）。检查：三件事读完，人物最后必须比开头更接近某个决定。

## B. 衔接侧（3 项）

### B1. 上一回结尾的「未闭合动作」清单

读上一回末 200 字，逐项记：

| 要抓的东西 | 为什么 |
|---|---|
| 最后一个动作是谁做的、做到哪一步 | 本章第一段必须接住 |
| 最后一句是谁说的、对面有没有反应 | 反应缺失=断层 |
| 时间点（白天/夜里/几更） | 本章开头不许倒退 |
| 在场有几个人 | 少一个=人间蒸发 |
| 有没有未落的危险 | 不许本章开头就当没发生 |

**五样必须全部记下**，缺一样就是「无前文可接」的变体，要回读更前面。

### B2. 本章开头的时间距离

本章故事时间距离上一回结尾有多久？三种取值，选一种并写进开头的第一个句子或第一段：

- **零间隔**（紧接着）：第一句必须是上一回最后一个动作的延续。
- **短间隔**（几小时到一天）：第一段要交代这段时间里发生了什么（一句就够）。
- **长间隔**（数天以上）：必须用一句时间锚点开头，且要交代这段时间的**代价**（不是「三天后」，是「三天后，他的伤结了痂，令牌还没找到」）。

**禁止**：无交代的跳跃。读者会以为是漏章。

### B3. 上一回埋的钩子，本章兑现了没有

上一回的 `hook` 是「他推开门，看见里面坐着的人」。

- 本章第一段必须处理它：要么给答案，要么明确延后（延后必须给理由，如「他没看清，因为灯灭了」）。
- **不许**整章不提，那会让读者觉得被骗。这是掉读的第一大原因。

## C. 人物侧（3 项）

### C1. 每个出场人物都有卡，且卡上有本章需要的字段

逐人核对本章用得上的字段：

| 本章有什么戏 | 卡上必须有的字段 |
|---|---|
| 有对白 | `voice`（语言基因） |
| 要做一个艰难决定 | `threshold`（心理阈值 + 破例条件） |
| 要展示能力 | `rules` 里对应的 `allow` / `forbid` |
| 与另一人互动 | `relation`（带方向） |
| 状态有变（伤、知道什么） | `state` |

**缺卡不许编。** 编出来的口吻会在三章后崩，且审校查不出来（因为账本上没有）。

### C2. 在场人数是否可控

**单场景出场人物 ≤5 人**，超过 5 人时读者分不清谁在说话。超过时：

- 改成两场（走一批人）。
- 或者给每个超过的人一个**单字辨识特征**（疤、口音、兵器），且第一次出现时必须点出来。

### C3. 谁在这章里「不说话」

有台词的人好写，没台词的人最容易变道具。逐人问：**他这个场景在做什么？**

答不出 → 要么给他一个动作（递东西、挡路、退半步），要么让他不在场。

**判法**：本章出场但零动作零台词的人物数 = 0。有就是「人形背景板」。

## D. 篇幅侧（2 项）

### D1. 单回字数与推进点配额

```
单回目标字数 = targetWords ÷ 总回数（±15%）
推进点配额 = 单回目标字数 ÷ 每推进点字数
```

`pacing` 为快节奏（800–1000 字/推进点）时，3000 字章 = 3–4 个推进点。标准（1200–1500）时 = 2 个。

**动笔前先决定这 2–4 个推进点分别落在哪一段**。不预先分，写完必然有一大段空转。

### D2. 场景数

| 单回字数 | 场景数 |
|---|---|
| 2000–2500 | 1–2 |
| 2500–3500 | 2–3 |
| 3500–4500 | 3–4 |

场景数 >4 且字数 <3500 → 每个场景都会太薄。砍场景，不要砍场景内的东西。

---

## E. 动笔前的最后一张单子

写完 A–D 十二项后，用这张单子做最终确认。任何一项答「否」，不许动笔：

- [ ] 三件事分属 ≥2 类变化，且有一类是主导
- [ ] `hook` 能用 40 字以内写出来
- [ ] 与 `rules` / `foreshadow` 无明文冲突
- [ ] 三件事能串成「因为…所以…」
- [ ] 上一回末 200 字读过，五样都记了
- [ ] 本章开头的时间距离已选定
- [ ] 上一回钩子已兑现或已给延后理由
- [ ] 出场人物全有卡，关键字段齐
- [ ] 单场景 ≤5 人，无背景板
- [ ] 推进点配额已分配到段
- [ ] 场景数与字数匹配

十一项全过，开始写第一段。
