## 参考层

- `references/l1-l2-l3-layers.md` —— 上下文的三层切分：每层放什么、什么时候上升、压测怎么跑
- `references/recall-drift-symptoms.md` —— 记忆漂移的八个症状：出现哪一条说明该重建摘要

# 上下文管理

三层记忆的取用规则。目标只有一个：**写到第 300 章，仍然像第 3 章一样记得清**。

## 三层结构

| 层 | 存什么 | 大小 | 怎么用 |
|---|---|---|---|
| **L1 资产** | 账本八类 + 风格卡 + 读者画像 + 世界规则 | 常驻，要压缩到能一次塞进上下文 | 每次开工都预热一遍 |
| **L2 片段** | 与本章相关的原文段（上一回末 200 字、伏笔埋设处原句、角色首次出场描写） | 按需召回 | 只在写具体段落时拉 |
| **L3 摘要** | 已写章节的逐章摘要（每章 3 句 + 钩子） | 随章数线性增长 | 超出窗口时，用 L3 替代原文 |

## 执行步骤

**第 1 步：预热 L1（每次开工必做）**

按固定顺序拉一遍，缺项要点名：

1. `outline.get` → 本卷结构 + 本回细纲
2. `ledger.get` → 八类账本（`characters` 只取本章出场者 + 相关者）
3. `project.get` → `worldState`、`targetWords`、`qualityGate`
4. 风格卡（若有）
5. 读者画像卡（若有，来自 `changye-reader-persona`）

L1 的目标是「一眼能答：这章谁出场、他要干什么、不能违反什么」。

**第 2 步：按需召回 L2**

只在下列三种情况拉原文，不要整章整章读：

| 需求 | 召回什么 | 取多少 |
|---|---|---|
| 接续语气 | 上一回末尾 | 200 字 |
| 伏笔兑现 | 该伏笔埋设处原句 | 1-2 句 |
| 首次出场描写 | 该角色/地点第一次出现的段落 | 1 段 |

**第 3 步：建 L3 摘要（写到约 50 章后必须有）**

每章摘要三段式：

```
第 N 回 | <回目> | ① 起因：<一句> ② 变化：<一句> ③ 落点：<一句> | 钩子：<一句>
```

摘要只记**发生了什么**，不记怎么写的。写完之后，讨论远期情节时只读 L3，不读原文。

**第 4 步：判断该用哪一层**

```
这个问题需要知道「具体怎么写的」？ → 是：L2 原文
                                 → 否：继续问
需要知道「当时到底发生了什么」？ → 是：L3 摘要
                                 → 否：L1 账本就够
```

**第 5 步：报告记忆健康度**

写完一章后检查：本章有没有用到「L1 里查不到、但前文写过」的信息？有 → 说明 L1 有缺口，要补进账本。

## 输入

- `changye_op` 的各路读接口（`outline.get` / `ledger.get` / `project.get` / `chapter.get` / `chapter.list`）
- 已有 L3 摘要（若已建）

## 输出格式

```
【L1 预热】outline <有/无>｜ledger <八类齐全 n/8>｜project <有/无>｜风格卡 <有/无>｜读者画像 <有/无>
【缺项】<哪类为空 → 建议谁去补>
【L2 本次召回】
  上一回末 200 字：<已取/不需要>
  <伏笔名> 埋设句：「<…>」
  <角色> 首次出场段：第 <n> 回
【L3 状态】已建 <n> 章摘要 / 共 <n> 章 → <够用/需补齐/未建>
【记忆缺口】<本章用到但 L1 查不到的信息 → 要补进哪类账本>
```

## 检查清单

- [ ] L1 五项逐项检查过，缺项已点名
- [ ] 没有整章读原文（只在三种情况召回 L2）
- [ ] 每次 L2 召回都记了「为了什么」
- [ ] 章数超 50 时 L3 摘要已建
- [ ] 摘要格式是三段式 + 钩子，不是剧情概述
- [ ] 本章用到的旧信息都能在 L1 找到，找不到的已记成缺口
- [ ] 没有把 L1 塞成一堆无关角色

## 禁止事项

- 不许生成正文。
- 不许做质量判断（这章好不好不在这份手册的职责里）。
- 不许整本书通读来「找感觉」——那是 token 灾难。
- 不许把 L3 摘要写成文学评论。摘要只记事实。
- 不许跳过 L1 预热直接动笔。
- 不许在 L1 里塞入本章不相关的全部角色卡（会挤掉真正需要的）。
