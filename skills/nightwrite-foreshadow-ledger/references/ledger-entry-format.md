> 适用：要往台账里埋一条伏笔、或者查「这条伏笔的 note 该写什么才判得动」时读这份。

# 伏笔条目的字段与写法

台账的价值全在字段。字段写虚了，这条伏笔在盘点时就等于不存在——因为无法判定它收没收。

## 五个必填字段

| 字段 | 类型 | 判据 |
|---|---|---|
| `name` | 稳定标识 | 全书唯一，永不改 |
| `plantedAt` | 章号（整数） | 必须具体到回 |
| `payoffAt` | 章号（整数） | 必须具体到回，不许填空/虚指 |
| `status` | 枚举 | `未回收` / `已回收` / `废弃` |
| `note` | ≤30 字文本 | 埋的时候正文里的那个具体句/物件 |

## `name`：为什么必须稳定

**判据**：这个名字在全书范围内，只有一条伏笔用。改一次名，等于把这条伏笔的历史切断——盘点时会出现「一条已回收、一条未回收」，实际是同一条。

**命名规则**：

| 规则 | 正例 | 反例 |
|---|---|---|
| 用物件/身份/事件的名，不用描述 | `半枚虎符` | `主角父亲留下的那个东西` |
| 3–8 字 | `户籍涂改` | `他户籍上那个被人改过的名字` |
| 不含章号、不含状态 | `井台两只碗` | `第16回埋的碗（未收）` |
| 与 `terms` 里的专名一致 | `官凭` | `那个文书` |

**同一条伏笔的别名问题**：正文里可以用不同说法（半枚虎符 / 那半块铜 / 父亲留下的东西），但台账里只有一个 `name`。别名不进台账。

## `plantedAt`：埋在哪一回

**判据**：正文里**第一次**让这个物件/信息出现的那一回。

三种常见的埋设形态，章号取法：

| 形态 | 正文表现 | `plantedAt` 取 |
|---|---|---|
| 明写 | 直接给出物件和信息 | 该回 |
| 暗写 | 只给一个反常细节，不解释 | 该回（这就是埋设点） |
| 前提埋设 | 埋的是后续可能的条件（这个人物有钥匙） | 该回 |

**不许的取法**：
- 取「构思的时候想到的那一回」——台账记正文，不记构思
- 取「主要写这件事的那一回」——伏笔的埋设点往往是轻描淡写的一句

## `payoffAt`：收在哪一回（最硬的字段）

SKILL 的硬规则：**`payoffAt` 写不出来的伏笔不许入账**。

理由：写不出回收章号，说明这条「伏笔」只是随手写的细节，或者作者还没想好怎么收。前者不该入账（它不是伏笔），后者入账后会变成超期债。

### 怎么写出一个可信的 `payoffAt`

不是猜，是**推**。三种方法：

**方法一：从结算倒推（最可靠）**

这条伏笔服务于哪个结算？那个结算在第几回？→ `payoffAt` 就在结算前 1–3 回。

例：`半枚虎符` 服务于「主角与父亲关系的结算」（第 30 回）→ `payoffAt = 第 28 回`（结算前先兑现信物）。

**方法二：从卷结构定**

这条伏笔的信息量适合在哪一卷释放？

| 伏笔的信息量 | 适合的卷位 |
|---|---|
| 只影响一场戏 | 埋设后 3–8 回 |
| 影响一条支线 | 本卷末（埋设卷 +5 到 +15 回） |
| 影响主角的身份认知 | 跨卷，通常在第二卷或第三卷的结算处 |
| 影响全书格局 | 最后一卷，且必须在最终结算前 |

**方法三：从可忍上限反推**

读者能等多久？参照 `emotional-payoff` 的甜点上限（≤10 章）：伏笔的可忍上限接近甜点，因为性质相同（都是「等一个东西」）。

| 伏笔类型 | 可忍上限 |
|---|---|
| 物件型（半枚虎符、一封未拆的信） | ≤15 回 |
| 信息型（某人的真实身份） | ≤25 回 |
| 关系型（两人其实是兄妹） | ≤30 回 |
| 世界型（这个世界的一条隐规则） | 可到卷末，不设上限 |

超过上限的伏笔，必须在中间**有一次中途提及**（不需要兑现，只需让它再出现一次），把读者的记忆续上。

### `payoffAt` 允许调整吗

允许，但要留痕。

| 情况 | 处置 |
|---|---|
| 提前收（原定 30 回，实际 24 回收了） | 改 `payoffAt` = 24，`note` 里加「原定 30」 |
| 推后（原定 24，改成 30） | 改 `payoffAt` = 30，`note` 里加「延后，原定 24」，且必须在本卷内找一处中途提及 |
| 无限推后 | 不许。超过三次改期 → 改成 `废弃`，写明理由 |

**三次改期规则**：一条伏笔的 `payoffAt` 改过 3 次以上，实际上等于没有回收计划。这时要么当卷收掉，要么废弃。

## `note`：30 字里装什么

`note` 是这条伏笔唯一能被验证的实物证据。它必须能让一个没读过这一章的人，翻到那一章就能找到那句话。

### 正确的写法

```
note: 「井台边放着两只碗，院主说他一个人住」
note: 「官凭上「沈」字被改过，墨色比旁边的深」
note: 「他左手接茶时抖了一下」
```

**三个特征**：可检索（有具体名词）、可验证（能对上原文）、不解释（不写「这意味着……」）。

### 三种坏写法

| 坏写法 | 问题 |
|---|---|
| `主角父亲留下的重要信物` | 无可检索名词，翻原文找不到 |
| `关于身份的重要线索` | 抽象，等于没写 |
| `井台两只碗，说明院主在撒谎，暗示他儿子还活着` | 超 30 字 + 写了推断（推断会随剧情变化，句子不会） |

**`note` 不写推断的理由**：推断是作者当时的理解，三个月后可能变了；而正文里那句话永远不变。台账记不变的，不记会变的。

### 回收后的 `note`

回收后 `note` 变成两段（用 `｜` 分隔）：

```
note: 「井台边放着两只碗，院主说他一个人住」｜收：「碗是给他儿子的，他每晚摆一副」
```

**回收后的 note 必须包含兑现句**（≤30 字），这是 SKILL 第 2 步的硬要求。只说「已经收了」不算。

## `status`：三态与超期的处理

| 状态 | 判定条件 | 需要什么 |
|---|---|---|
| `未回收` | `payoffAt` 还没到 | 无 |
| `已回收` | 正文里确实兑现了 | 必须能引出兑现句 |
| `废弃` | 主动放弃 | 必须写理由 |

**超期不是第四态**：`payoffAt < 当前最大章号` 且 `status = 未回收` → 超期，是 `未回收` 的子情况。

**超期的两个子档**（SKILL 没细分，实操需要）：

| 子档 | 判据 | 处置 |
|---|---|---|
| 软超期 | 超 ≤3 回 | 本轮补收，或改期一次 |
| 硬超期 | 超 >3 回 | 必须报进欠账，不许自己消化 |

### 废弃的两种合法理由

1. **埋设场景被删**：改稿时删掉了埋设点，这条伏笔失去了起算点。
2. **兑现场合永久错过**：本该在那个场合收的人已经死了/走了，且无法替代。

**不许的废弃理由**：
- 「这条不好收」——这是偷懒，不是理由
- 「读者应该忘了」——读者可能忘了，但改稿时会撞上
- 「太长了，砍掉」——砍掉前先看它有没有连带其他伏笔

**废弃必须留痕**：`note` 里加 `废：<理由>｜原 payoffAt 第 N 回`。不许直接删行。

## 字段之间的相互约束

### `payoffAt` 必须晚于 `plantedAt`

```
payoffAt > plantedAt  （严格大于，同回收不算伏笔，算当场解决）
```

**同回埋同回收的情况**：这不是伏笔，是**场景内的悬念**。不进台账（进 `chapter-hook` 的钩子管理）。

### `payoffAt` 不能落在不存在的章

必须先有 `outline`。`payoffAt` 指向的章号如果不在这卷的章表里 → 入账时就要报错。

### `plantedAt` 不能晚于当前最大章号

如果 `plantedAt` 在未来（还没写），这条是**计划中的伏笔**，不是已埋的。台账只记已埋的。计划中的伏笔放在卷纲里，不入台账。

**这条的目的**：防止作者为了「台账好看」提前入账一堆没埋的伏笔，实际埋的时候写不出来。

## 入账前的五项确认

```
- [ ] name 全书唯一，且与 terms 的专名一致
- [ ] plantedAt 是正文里第一次出现的那一回（不是构思的那回）
- [ ] payoffAt 是具体章号，且 > plantedAt，且该章在 outline 里存在
- [ ] note 有可检索的具体名词，≤30 字，不写推断
- [ ] status = 未回收
```

五项缺一 → 不入账。SKILL 的硬规则「有埋没回收章的不许入账」，本质就是第 3 项。

## 台账模板

```
【伏笔台账】截至第 <n> 回
name | plantedAt | payoffAt | status | note
半枚虎符 | 12 | 28 | 未回收 | 「他摸出半枚铜，缺的那半在父亲手里」
井台两只碗 | 16 | 19 | 已回收 | 「井台边放着两只碗，院主说他一个人住」｜收：「碗是给他儿子的」
官凭涂改 | 20 | 34 | 未回收 | 「官凭上「沈」字被改过，墨色比旁边深」
旧案卷宗 | 20 | — | 废弃 | 废：第 22 回改稿删了书办房那场，起算点没了｜原 payoffAt 第 30 回

【统计】未回收（未到期）<n>｜软超期 <n>｜硬超期 <n>｜已回收 <n>｜假回收 <n>｜废弃 <n>
【超期清单】<name>（应于第 <b> 回，已逾 <n> 章）— 处置：<补收/改期/废弃>
【假回收】<name>（标已收但引不出正文句）
```

## 一个反直觉的结论

**`note` 写得越像原文，这条伏笔的存活率越高。**

原因：`note` 是回收时唯一的对照物。如果 `note` 是「关于身份的重要线索」，回收时你会想「我记得当时埋的是什么来着」，然后凭印象写，写出来的东西和原文对不上——读者会觉得「这不是同一个东西」。

如果 `note` 是「官凭上「沈」字被改过，墨色比旁边深」，回收时你只需要让那个墨色深的地方再出现一次，读者会立刻认出。

**所以 `note` 的质量决定伏笔的回收质量**，它比 `payoffAt` 更重要——`payoffAt` 可以改期，`note` 写坏了无从补救。
