- `references/beat-types.md` —— 节拍的六种类型：各自的功能、出现频率、连续同类节拍的处理

# 节拍表

把「主线」拆成**能数得清、能对得上章号**的节拍序列。节拍不是大纲——大纲说「写什么」，节拍说「什么时候必须发生什么」。

## 节拍的五种类型

| 类型 | 作用 | 频率 |
|---|---|---|
| **钩子节拍** | 抛出新问题/新威胁 | 每 1-2 章 |
| **升级节拍** | 赌注变大（要输的东西更贵） | 每 3-5 章 |
| **反转节拍** | 已知信息被推翻 | 每 5-8 章 |
| **代价节拍** | 主角付出一项不可逆的失去 | 每 8-12 章 |
| **结算节拍** | 兑现一个悬了很久的承诺 | 每卷 1-2 次 |

## 执行步骤

**第 1 步：先定这一卷要结算什么**

从 `outline.get` 读卷 `summary`，写出一句：「这卷结束时，读者应该看到_____被解决/被兑现。」

答不出来 → 这卷没有节拍可言，先回 `nightwrite-plan-novel`。

**第 2 步：倒推节拍**

从这个「结算」往回推到卷首，逐段问：

```
要发生这个结算，前面必须先发生什么？
```

连问 5-8 次，得到一串倒推链。每一环就是一个节拍。

**第 3 步：给每个节拍标四件事**

```
序号 | 章号 | 类型 | 谁的选择 | 代价
```

- **谁的选择**：节拍必须由**某个角色的决定**驱动，不是「事情发生了」。
- **代价**：这个节拍让谁失去了什么。没有代价的节拍是过场，不是节拍。

**第 4 步：检查分布**

- 有没有连续 5 章以上没有「升级」或「反转」？→ 中段会塌。
- 代价节拍是不是全挤在卷末？→ 前期会没有重量。
- 结算节拍后面有没有立刻接新钩子？→ 没有的话读者会在结算处合书。

**第 5 步：落盘**

写进 `outline.save` 的卷 `summary`（节拍表摘要）+ 各回 `summary`（节拍落地）。节拍表本身可以另存为 `ledger.upsert` kind=`highlights`。

## 输入

- `outline.get`：卷结构与各回 `summary`
- `chapter.list`：已写到第几回（重排时已写的章必须保留其节拍功能）
- `ledger.get`：`conflicts`（冲突赌注）、`foreshadow`（结算节拍常与伏笔回收重合）

## 输出格式

```
【本卷结算】<这卷结束时读者看到_____被解决>
【倒推链】结算 ← <前一步> ← <再前一步> ← … ← 卷首
【节拍表】
  #1 | 第 <n> 回 | 钩子 | 谁的选择：<…> | 代价：<…>
  #2 | 第 <n> 回 | 升级 | 谁的选择：<…> | 代价：<…>
  #3 | …
【分布检查】
  最长无升级/反转区间：第 <a>-<b> 回（<n> 章）→ <可接受/需插入>
  代价节拍位置：<第几回> → <前置/挤在卷末>
  结算后是否接新钩子：<是（第 n 回）/否>
【落盘】<写到哪>
```

## 检查清单

- [ ] 本卷「结算」写得出具体一句话
- [ ] 倒推链至少 5 环，每环都能回答「必须先发生什么」
- [ ] 每个节拍都标了类型、章号、谁的选择、代价
- [ ] 没有「事情发生了」型节拍（必须由角色决定驱动）
- [ ] 没有代价的节拍已删除或补上代价
- [ ] 分布检查三项都做了
- [ ] 结算节拍后接上了新钩子
- [ ] 已落盘

## 禁止事项

- 不许写正文、不许写对白示范。
- 不许查设定冲突。
- 不许写「主角变强了」这种没有代价的节拍。
- 不许让节拍由巧合驱动（「恰好遇到」「正好捡到」）。
- 不许把所有高潮堆在卷末。
- 不许节拍数量超过章数（一个节拍可以跨多章，但不能一章塞三个节拍）。
