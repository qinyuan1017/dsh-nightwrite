# 人物状态卡

只记录**当前状态**，不设计角色。作用是防止「成长弧光漂移」和「提前知道不该知道的事」。

## 状态卡五项

| 字段 | 记什么 | 用来判什么 |
|---|---|---|
| 已知 | 他现在知道哪些关键信息 | 他说的话有没有超出认知 |
| 持有 | 物件、武器、钱、凭证 | 他能不能用某个东西 |
| 关系 | 对每个人当前的态度与信任度 | 他的反应合不合理 |
| 损伤 | 身体伤、心理创伤、能力损耗 | 他能不能做某件事 |
| 位置 | 他现在在哪 | 时间线能不能对上 |

## 执行步骤

**第 1 步：读上一状态 + 这一章发生了什么**

- `ledger.get` → `characters` 找该角色现有 `state`；
- 读本章正文，列出**改变了什么**：知道了新信息 / 得到或失去物件 / 关系变好变坏 / 受伤或恢复 / 移动了位置。

只有真的变了才更新。没变就写「无变化」，不要为了更新而更新。

**第 2 步：改状态（逐项，不整段覆盖）**

`ledger.upsert`（kind=`characters`，同一个 `id`）只改动变了的那几项。

**第 3 步：做三项一致性自查**

1. 本章他说的话，有没有用到「已知」里没有的信息？
2. 本章他做的事，有没有违反「损伤」的限制（受伤还打满场）？
3. 本章他对某人的反应，跟「关系」的当前值一致吗？

**第 4 步：记录变更点**

状态卡的更新必须带「因为第几回发生了什么事」，否则以后没人知道这个状态是从哪来的。

## 输入

- `ledger.get` 的 `characters`（现有 `state`）
- 本章正文（`chapter.get`）
- `outline.intent`（这一回本来要发生什么）

## 输出格式

```
【角色】<名> · id=<…>
【变更项】（无变化则只写「无变化」）
  已知 += <新知道什么>（来自第 <n> 回：<事件>）
  持有 -= <失去什么>
  关系 <对A：<旧> → <新>>（原因：…）
  损伤 += <…>
  位置 <旧> → <新>
【三项自查】
  认知越界：<有/无 — 哪句>
  伤情越界：<有/无 — 哪句>
  关系越界：<有/无 — 哪句>
【落盘】ledger.upsert 成功
```

## 检查清单

- [ ] 先读了现有 `state`，不是凭空重建
- [ ] 只改动了真正变化的项
- [ ] 每个变更项都写了「来自第几回什么事件」
- [ ] 认知/伤情/关系三项自查都做了
- [ ] 用的是同一个 `id`，没有新建重复角色
- [ ] `ledger.upsert` 已执行

## 禁止事项

- 不许设计新角色、改人物底色、改成长弧光——那是 `changye-character-arc`。
- 不许改主线或卷结构。
- 不许为了让本章通顺而给角色「临时知道」某事。
- 不许整段覆盖 `state`（会丢掉历史变更点）。
- 不许把「状态」写成性格描述（「他现在很痛苦」不是状态，「左臂骨折未愈」才是）。
