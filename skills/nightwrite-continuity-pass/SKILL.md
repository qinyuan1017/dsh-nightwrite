# 一致性检查

只判**事实有没有崩**，不判好不好看。输出直接决定这一章能不能进定稿。

## 执行步骤

**第 1 步：拉全八类账本**

`nightwrite_op` → `ledger.get`，取出 `characters / locations / foreshadow / events / terms / rules / highlights / conflicts`。任何一类空着就是审计盲区，要在报告里点名「该类无数据，无法核对」。

**第 2 步：逐段抽取事实断言**

把正文读一遍，凡是能证伪的句子都抽出来，写成「主体 + 属性 + 值」：

```
第 3 段：主角（主体）· 父亲生死（属性）· 已死三年（值）
第 7 段：主角（主体）· 独子（属性）· 是（值）
```

共情句、感受句、修辞句不抽（「他心里一沉」不是事实断言）。

**第 3 步：四维比对**

| 维度 | 比什么 | 典型冲突 |
|---|---|---|
| 事实 | 抽出的事实 vs `characters / locations / terms` | 姓名写法、外貌、身份、能力上限、物件归属 |
| 伏笔 | `foreshadow` 的「收于第 b 回」vs 当前章 | b ≤ 当前章但正文没出现 = 断线 |
| 时间线 | 相邻两回的 `events` 交叉 | 先后颠倒、季节错、行程耗时不可能 |
| 人物行为 | 行为 vs `characters` 的「心理阈值 / 语言基因」 | 做了他绝不做的事、说了他绝不说的话 |

**第 4 步：定级（只有三条规则）**

- **致命**：与账本**明文**冲突；或伏笔应收未收。→ 不可签发
- **警告**：账本没记，既不能证实也不能证伪。→ 可签发，需备注
- **通过**：零致命（允许有警告）

**第 5 步：给可执行的建议**

每条致命/警告后面必须跟一句「怎么改」，但**不许写成改写稿**。写「把『独子』改成『长子』或删掉这句」，不写「第 3 段改成……」

## 输入

- 待审正文（`chapter.get` 或交来的稿）
- `ledger.get` 八类全量
- `project.get` 的 `worldState`（世界当前状态基线）
- 最近两回 `chapter.get`（时间线交叉用）

## 输出格式

```
【判定】致命 <n> / 警告 <n> → <不可签发 / 可签发>
【致命】
1. 第 <X> 段「<原文 ≤30 字>」
   ↔ <账本类>/<条目> 记「<账本原话>」
   建议：<一句话怎么改>
【警告】
1. 第 <X> 段「<原文>」｜账本无此信息，无法证实：<具体疑点>
【伏笔】
  已收：<名>（第 N 回）
  应收未收：<名>（应于第 b 回，未见）
  超期：<名>（已逾 b 回 n 章）
【通过项】事实 <n> 项 · 伏笔 <n> 条 · 时间线 <n> 段 · 人物行为 <n> 处
【审计盲区】<哪类账本为空、哪几回没读过>
```

`【致命】` 段在没有致命时**必须显式写「无」**，不许省略整段——省略会让人误以为漏查。

## 检查清单

- [ ] 八类账本全部拉取过，空的类别已在「审计盲区」点名
- [ ] 正文逐段抽过事实断言，不是只挑眼熟的比对
- [ ] 四个维度逐个过了一遍，没有哪一维被跳过
- [ ] 每条结论都带段号 + 原文引用（≤30 字）
- [ ] 每条都引用了账本具体条目名，不是「与设定不符」
- [ ] 伏笔分了三态（已收/应收未收/超期）
- [ ] 致命项没有为了省事降级成警告
- [ ] 没有出现审美判断（「太拖」「不够爽」）
- [ ] 没有提供改写稿，只提供改法方向
- [ ] `【致命】` 段存在（哪怕是「无」）

## 禁止事项

- 不许改写正文。一个句子都不替别人改。
- 不许评价好不好看。那不在这份手册的职责里。
- 不许决定发布/签发。
- 不许审文风、不许查 AI 味——发现了也不写进报告，会污染判定等级。
- 不许用「整体感觉有点乱」「有些地方对不上」这种无法定位的表述。
- 不许因为「改起来麻烦」把致命降成警告。
- 不许在账本缺数据时给「通过」。盲区只能是「警告 + 点名」。
